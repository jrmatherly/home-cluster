# Media (`[media]`)

- `[media]` in `cluster.toml` (an NFS server address, which gates the section, a worker name, a timezone, five new random API keys for Sonarr, Radarr, Prowlarr and SABnzbd, the ID and secret of an OIDC client created by hand in Pocket ID with one callback URL per app, a `recyclarr` flag, and an optional `plex_host` and `plex_token` pair, and an optional `public` flag, which needs `pocket_id.public`; needing `[pocket_id]`) gates the `media` namespace, which enforces the `restricted` pod security level, and `storage/csi-driver-nfs`, the NFS CSI driver from its classic Helm repository (one of the repo's two `HelmRepository` sources, with `rustfs`), with `feature.enableFSGroupPolicy: false` so the kubelet never chowns the share to a pod's `fsGroup` (the walk over the whole export fails while SABnzbd is writing and the export squashes every client to one uid anyway). `media/shared` holds one static CSI `PersistentVolume` and its pre-bound `ReadWriteMany` claim `media` for the host's export (`nfsvers=4.1,hard,noatime,nolock`, because Talos runs no `rpc.statd`), the `media-keys` Secret (every API key and the Plex token; each app reads its own key and the keys of the apps it talks to from it), the `media-oidc` Secret every app's `SecurityPolicy` reads, and the namespace's one NetworkPolicy, which admits only the `network` namespace and the stack's own pods to every pod, because the arrs trust whoever reaches them. The PV carries a `nodeAffinity` for `media.node`, so the scheduler keeps every claimant on that node, which `nolock` requires. Each app is on the app-template chart, runs as uid 1000 (the export squashes every client to 1000), mounts the claim at `/data` in the TRaSH layout, keeps its config on a `local-path` volume, and is pinned by `nodeSelector` to `media.node`, the worker whose Proxmox host serves the export, so NFS traffic never leaves that host. The arrs run with `AUTH__METHOD=External`, so the gateway's Pocket ID sign-in and that NetworkPolicy are the login: one `SecurityPolicy` in `media/shared` (a copy of Hubble's, admitting `cluster_admins`) selects every HTTPRoute labelled `media.sign-in: pocket-id` through `targetSelectors`, so a new app opts in with that label on its UI route and the shared file never changes, and leaves `redirectURL` unset so the gateway derives each route's own callback; a second HTTPRoute per app serves `/api` without the policy on the internal gateway only, so the API key is the credential there, as upstream. `public = true` also attaches every UI route to `envoy-external`, so the tunnel reaches them behind the same policy (Seerr behind its own login instead), while the `/api` routes stay internal. Every app starts fresh, with no carry-over from the Windows install; only the Usenet server and the indexers are typed once into SABnzbd and Prowlarr. Each HelmRelease carries a `configure` controller of `type: job`, annotated as a Helm post-install and post-upgrade hook, that runs an inline shell script from the `alpine/k8s` image against the app's API and converges the TRaSH and Servarr wiki settings idempotently (GET, compare, PUT for config singletons; upsert by name for providers), so helm-controller waits for it and a failed run fails the release; the HelmRelease `timeout` is 30m for that reason, the Service names its `controller` because the chart refuses a Service once a second controller exists, every wait on another app is capped at five minutes so an outage fails the release fast, and the job carries the `media_keys_checksum` computed field as an annotation so a rotated key re-renders the release and re-runs the hook. SABnzbd's script sets folders, the `tv` and `movies` categories and the switches through `set_config` with a read-back check, because a bad value is dropped silently; its host whitelist comes from an env var the entrypoint writes, and `verify_xff_header` is off, because the gateway is the only way in and signs users in, so a forwarded public address is not refused (the hook sets it through `set_config`, which works on 5.1.3; SABnzbd's development branch marks the key protected, so a later image bump makes that line fail the release, and the fix then is an init container editing `sabnzbd.ini`). The SABnzbd container has a 2-core CPU limit and the hook sets `pause_on_post_processing` to 1, because unbounded it took every vCPU on the host it shares with Plex and stalled a direct-play stream each time a large file completed (measured 2026-10-08). Sonarr's and Radarr's scripts wait for their SABnzbd category, then set media management, the root folder (plus `/data/ext/tv` or `/data/ext/movies` as a second root folder when that directory exists in the mount, which is the media host's parity-protected USB tier exported inside the same tree), SABnzbd as the download client and the Plex connection when `plex_token` is set; Prowlarr's waits for both arrs, then adds them as applications on Full Sync, because saving an application tests the round trip; no app Kustomization depends on another, since `wait` is false everywhere and Ready would only mean applied. Recyclarr (when `recyclarr = true`) is a CronJob at 06:00 UTC plus the same hook Job: an init container waits for both arrs, a second init container (`dependsOn` the first, which is how app-template orders them) runs `recyclarr sync` from a ConfigMap (TRaSH WEB-1080p and WEB-2160p, HD Bluray + WEB and UHD Bluray + WEB, quality definitions, Plex naming, Language: Not English, propers and repacks Do Not Prefer) with its state on a 1Gi volume, and the main container then deletes the six stock quality profiles (Any, HD - 720p/1080p, HD-720p, HD-1080p, SD, Ultra-HD) from both arrs, because Recyclarr never removes them and the add dialog defaults to one; a profile a title still uses is kept, and an app with no Recyclarr profile keeps them all. The same ConfigMap holds a `settings.yml` with a local `custom-formats` resource provider for Sonarr and its `Size: 2160p over 16 GB` format as JSON, scored -10000 in WEB-2160p, because no TRaSH format tests size and a quality definition is per minute of runtime; `delete_old_custom_formats` is on for both apps, so a format dropped from the config is removed, which is why a format's `trash_id` is never renamed in the same change that drops or adds one. Movies are capped in two steps: Radarr's hook sets the indexer Maximum Size to 16 GiB (`maximumSize = 16384`), Radarr's own absolute limit on any grab in every profile, which is the UHD Bluray + WEB cap and holds with Recyclarr off; Recyclarr's local `Size: over 12 GB` format (`radarr-size.json`, scored -10000 in HD Bluray + WEB only) holds the HD profile at 12 GB, a hard reject because the profile's minimum format score is 0. Under 16 GB and TRaSH's per-minute minimums (measured 2026-10-08: WEBDL-2160p 34.5 MB/min, Bluray-2160p 102 MB/min), the UHD profile admits WEB-DL 2160p up to about 7 hours and Bluray-2160p up to about 160 minutes; Remux is not in the profile at all. A long film that gets nothing there belongs on HD Bluray + WEB. Verified end to end against the pinned Sonarr and Radarr images on 2026-10-08. The scripts contain no `${`, because Flux post-build substitution would rewrite it. The `public` fixture sets the section with every optional field. SABnzbd's `set_misc` read-back normalises JSON booleans to 1/0, because `set_config` answers `true`/`false`, and Recyclarr's HelmRelease sets `install.disableWait` and `upgrade.disableWait`, because Helm's wait would hold its `WaitForFirstConsumer` claim until the timeout while the hook Job that binds it runs only after the wait. The second wave has no configure hook, and each app is set up once in its UI (`private/media-setup.md` section 7). Bazarr (`bazarr.`, subtitles, mounts the media claim at `/data`) cannot take its API key from env or a flag, and its providers need the operator's credentials. Tautulli (`tautulli.`), Seerr (`requests.`) and Maintainerr (`maintainerr.`) are gated by `media_plex_enabled`, because none works without Plex. Tautulli gets the arrs' internal `/api` route without the sign-in, because Tautulli Remote calls `/api/v2` directly. Seerr has no OpenID Connect support and is the request front end for household members, so it keeps its own Plex sign-in and carries no sign-in label. Maintainerr has no authentication at all, so the gateway sign-in and the namespace NetworkPolicy are its only login, and it mounts no media because its rules act through the arr APIs. All four start under Sonarr's securityContext (read-only root, uid 1000, every capability dropped), measured in Docker.
