# Docs site

- `docs/` is the public documentation site, so pages hold placeholders, never real values: hosts by role, `${SECRET_DOMAIN}`, angle-bracket placeholders. Pages under `docs/src/content/docs` are converted from the gitignored `private/` guides, in `docs/src/content/docs/{architecture,hosts,apps,operations,decisions}/` (every `cluster.toml` section with hand steps has a page under `apps/` as of 2026-10-12): the directory tree is the sidebar, each section's `index.mdx` is its landing, and the two `decisions/` records condense the private plan documents. `.claude/rules/docs.md` (loads on `docs/src/content/**` edits) holds the page shape and placeholder conventions. `docs/scrub-check.sh` refuses private addresses, MAC or email addresses, long tokens (lowercase words joined by underscores are skipped, because those are Prometheus metric names) and strings from the denylist (CI secret `DOCS_SCRUB_DENYLIST`, local `private/scrub-denylist.txt`, passed to the Dockerfile as the BuildKit secret `scrub_denylist`). The Dockerfile also needs `--build-context gitdir=.git` for Last updated dates, and the build fails when any built page lacks a `<time datetime=` element. `.oxfmtrc.json` ignores `*.mdx`, because oxfmt collapses MDX component children onto one line. The Docs Image workflow (`.github/workflows/docs-image.yaml`) builds `ghcr.io/jrmatherly/home-cluster/docs` on pull requests without pushing, and pushes `latest` and `sha-<commit>` on `main`. The GHCR package must be public (checked by hand after the first push), because the Deployment has no pull secret and Renovate reads the digest anonymously; between a push and the image it builds, the pod sits in ImagePullBackOff and recovers on its own. A fork's pull request has no denylist secret and fails the build by design. The Flux app `docs/docs` serves it at `docs.${SECRET_DOMAIN}` on the internal gateway, and Renovate pins and moves the image digest (`.renovaterc.json5`). That takes two rules: `pinDigests: true` sits in a rule without `matchUpdateTypes`, because update types are only known after the lookup that `pinDigests` steers, and a second rule matching `pinDigest` and `digest` sets the schedule and automerge with `ignoreTests`, because the preset automerges the branch itself once its checks pass and no workflow runs on a Renovate branch, so without it the pin branch waits forever (measured 2026-10-10). The starter files under `docs/src/`, `docs/astro.config.ts` and `docs/AGENT.md` are in `.oxfmtrc.json`'s `ignorePatterns` (with `.mise/**`, which `mise fmt` owns), and `docs/AGENT.md` is also in `.markdownlint-cli2.jsonc`'s `ignores`, because they are byte-identical to the upstream Nimbus starter, which ships no formatter config, and formatting them would turn each into a local edit that `nimbus-docs diff --apply` can no longer overwrite. The `docs` namespace enforces `restricted` and is unconditional, since no `cluster.toml` section gates it. The app is a plain Deployment (not app-template) running nginx-unprivileged as uid 101 with a read-only root, `/tmp` on an emptyDir and probes on `/healthz`, and a NetworkPolicy admits only the `network` namespace on 8080; the image is `:latest` plus the digest Renovate pins, which moves with each CI push. That pin is the `linux/amd64` manifest inside the `latest` index, not the index digest, so comparing it with the index reports a move that is not there (measured 2026-11-11). The Dockerfile runs `npm run build` before `npm run lint:docs` and `npm run typecheck`, because nimbus-docs 0.16 and later read their lint rules from `.nimbus/lint.json`, which only a build writes (the scrub check still runs first). `docs/nimbus.json` records `lastReviewedNimbusVersion`, and nimbus-docs refuses to build when a non-optional review lies between it and the installed package (0.18.0's are all optional, so a build passed before the migrate on 2026-10-17; 0.19.0's `changelog-release-notes` review is required, so Renovate's bump PR failed its Docs Image build until the migrate ran by hand on 2026-10-25, and the site has no CLI-added changelog so that review is a skip), so a Nimbus upgrade bumps the dependency, runs `nimbus-docs migrate --yes` to record consent, applies the clean starter additions with `nimbus-docs diff <file> --apply`, and commits them together.
- The architecture diagram is `docs/public/diagrams/architecture.svg` (an Archify export), shown on the architecture page and in the README. The scrub covers `docs/public` too, so an export's embedded base64 font subsets trip the long-token rule and are removed; the SVG renders with the monospace fallback stack and animates with its own CSS. Redraw it from the templates when the request path or the GitOps path changes (drawn at bc8030f).
