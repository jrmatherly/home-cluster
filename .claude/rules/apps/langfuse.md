# Langfuse (`[langfuse]`)

- `[langfuse]` in `cluster.toml` (an AI KB project key pair `public_key` `pk-lf-...` and `secret_key` `sk-lf-...`, a `salt`, a 64-hex `encryption_key`, a `nextauth_secret`, the ID and secret of an OIDC client created by hand in Pocket ID with the callback `/api/auth/callback/custom` and restricted to `cluster_admins`, a `clickhouse_password` and a RustFS key pair, set all together, needing `[postgres.backup]`, `[redis]`, `[pocket_id]` and `[rustfs]`) gates the `langfuse` namespace, which enforces the `restricted` pod security level. `langfuse/langfuse` is Langfuse, LLM tracing for AI KB, from its chart (`oci://ghcr.io/langfuse/langfuse-k8s/charts/langfuse`, pinned by `OCIRepository` tag) with every bundled store off, at `langfuse.${SECRET_DOMAIN}` on the internal gateway, with no gateway `SecurityPolicy`, because it signs users in with Pocket ID itself (the chart's `langfuse.auth.providers.custom`, password form off). Sign-up stays on, because `AUTH_DISABLE_SIGNUP` also refuses a first Pocket ID sign-in, and every user the client admits joins the Home organization as admin (`LANGFUSE_DEFAULT_ORG_*`; not owner, which could delete it, and a membership that exists keeps its role). When `nvidia_enabled`, the namespace carries the `localai.ai/client` label and the chart's top-level `langfuse.additionalEnv`, which reaches both web and worker (the worker runs evaluators), sets `LANGFUSE_LLM_CONNECTION_WHITELISTED_HOST` to the LocalAI Service, because self-hosted Langfuse refuses an LLM connection to a private address; the project connection itself is made in the UI. Its stores: the CloudNativePG cluster `langfuse-db` (two instances, WAL archiving and a daily backup at 05:45; the chart reads only the password key of the generated `langfuse-db-app` Secret, with user and database `app` as values; no migration creates an extension, measured on the image), the namespace's Redis from `components/redis` (the chart builds `redis://default:$(REDIS_PASSWORD)@redis:6379/0`, which `requirepass` accepts, measured), a hand-written single-replica ClickHouse StatefulSet `clickhouse` (no operator and no Keeper, `CLICKHOUSE_CLUSTER_ENABLED=false`, uid 101, 20Gi `local-path`, no backup) and the RustFS bucket `langfuse-events` (the `rustfs_consumers` entry `langfuse`; the namespace carries `rustfs.storage/client`, and its Kustomization depends on `rustfs-provision`, because every ingested event is written to the bucket before the worker processes it). The ClickHouse image's entrypoint writes the `langfuse` user into `users.d` from the env on every start, so `users.d` and `/tmp` are emptyDirs and the root stays read-only; a `config.d` file mounted by subPath (beside the image's own listen config) removes the system log tables Langfuse never reads (`trace_log`, `text_log`, `opentelemetry_span_log`, `asynchronous_metric_log`, `metric_log`, `latency_log`), which otherwise grow until merges run out of memory, keeps `query_log` on a 7-day TTL instead of the image's 30, and logs to the console (measured on the image). Its password is in its own `clickhouse-auth` Secret, which the chart reads too, so rotating a Langfuse key does not restart the only replica. The web and worker images run as uid 1001 on a read-only root with `/tmp` (and the web's `.next/cache`) on emptyDirs, measured in Docker with every migration applied. The web container runs every migration before it listens (over 450 on a fresh install, 18 s in Docker), so a `postRenderers` patch gives it a startup probe of ten minutes, because the chart's own probes kill it part way (langfuse-k8s issues 272 and 427) and leave a failed migration; the HelmRelease `timeout` is 15m. On the first start the `LANGFUSE_INIT_*` env creates the Home organization, the AI KB project and its key pair from the section's pair, only when absent, so a later change to the pair must also be made in the project settings. Telemetry, batch export and PDBs are off, and so is the sign-up onboarding step (`LANGFUSE_DISABLE_SIGNUP_ONBOARDING`), which calls langfuse.com from the browser; the chart renders the media settings even with `mediaUpload.enabled: false` and Langfuse has no switch for media upload, so media lands under `media/` in the same bucket. The events bucket has no expiry, because Langfuse reads the objects back for trace detail, and trace retention in ClickHouse is an Enterprise feature, so the bucket and the 20Gi volume grow with tracing. A Renovate rule groups the web and worker images, and the pull policy stays `IfNotPresent`, because the chart's `Always` dials Docker Hub on every start, and Reloader restarts the pods that read a changed Secret. The `postRenderers` patch sets `enableServiceLinks: false` on the langfuse-web and langfuse-worker Deployments, because the namespace's `redis` and `clickhouse` Services make the kubelet inject `REDIS_PORT=tcp://...` into every pod, which Langfuse's env schema coerces to NaN and refuses to start on, and the chart has no switch for it (measured 2026-10-18). Never change `salt` (every API key stops working) or `encryption_key` (stored keys become unreadable). The `public` fixture sets the section, and the invalid fixtures `partial-langfuse`, `langfuse-without-rustfs`, `langfuse-bad-encryption-key` and `rustfs-duplicate-key` (the section reusing the RustFS root access key) cover its checks.
