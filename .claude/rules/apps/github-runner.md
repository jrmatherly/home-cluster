# Actions runner (`[github_runner]`)

- `[github_runner]` in `cluster.toml` (one `token`, a fine-grained PAT on this repository with Administration read and write, which GitHub requires to register a repository runner; it was made with no expiry, stated) gates the `actions-runner` namespace, which enforces the `restricted` pod security level. It runs Actions Runner Controller from two OCI charts that share a version and move together in one Renovate group: `arc-controller` (`gha-runner-scale-set-controller`) and `home-cluster-runners` (`gha-runner-scale-set`), whose Kustomization depends on the first because the scale set is a CRD the controller chart installs. The controller sets `flags.watchSingleNamespace`, so its RBAC is Roles in this namespace instead of a ClusterRole, and the scale set names it in `controllerServiceAccount`, because the chart cannot discover a single-namespace controller (stated, chart templates). The scale set is `home-cluster` (`runs-on: home-cluster`), with `minRunners` 0 and `maxRunners` 1, so only the controller and one listener pod run between jobs; it reads the PAT from `home-cluster-runners-secret` under the key `github_token`. The listener pod takes its security context only from `listenerTemplate` (stated, controller source). The runner image's user is the name `runner`, which `restricted` cannot verify, so the runner container sets uid and gid 1001; its root stays writable because `run.sh` and the tool installers write under `/home/runner`, sudo fails under no-new-privileges, and the ephemeral-storage limit is 8Gi because Claude Code, mise and the repo's tools wrote 2.4 GB there (all measured in Docker 2026-10-25). The runner's ServiceAccount `home-cluster-runner` has an explicit read-only ClusterRole listing the kinds the checks in `auto-checks.yaml` read (workloads, Flux objects, gateways, Prometheus and Alertmanager, certificates, CloudNativePG clusters, nodes, storage classes, CRDs and `metrics.k8s.io`), with no Secrets, no ConfigMaps (Flux substitutes keys into some) and no write on any object, plus `pods/log` in the `network` namespace only, for the two ExternalDNS log checks (that Role sits in `apps/network/runner-logs-rbac.yaml`, because the runner Kustomization's `targetNamespace` moves every object it applies into `actions-runner`, measured); it replaced the built-in `view` plus a `patch` grant on 2026-10-25 after the commit's security review, and the apply script no longer runs `flux reconcile`, because the flux-webhook Receiver and the GitRepository's one-minute poll pick the merge up. A `CiliumNetworkPolicy` with an empty `endpointSelector` limits every pod in the namespace to DNS in `kube-system`, the `kube-apiserver` entity, the internal gateway (Envoy's pod port 10443 in the `network` namespace and the gateway address on 443, for the health checks) and TCP 443 outside the computed `private_cidrs`. In `update-apps.yaml`, `CLAUDE_CODE_SUBPROCESS_ENV_SCRUB` makes Claude Code require its sandbox, and the action installs bubblewrap and socat only with `allowed_non_write_users`, so the workflow installs them itself; without them Bash refuses to start and the run still reads green with no verdicts (run of 2026-11-01). `operations/app-updates.mdx` has the rest of the research job's guards.
