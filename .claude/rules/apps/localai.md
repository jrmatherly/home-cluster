# LocalAI (`[localai]`)

- The whole `ai` namespace (`ai/localai` and its namespace and kustomization files) is wrapped in `#% if nvidia_enabled %#`, so it renders empty when NVIDIA is off.
- `[localai]` in `cluster.toml` (one `api_key` of at least 32 letters and digits, required whenever a node loads the nvidia kernel module) is the credential for `ai/localai`, LocalAI from the official images with no custom build: the main image `localai/localai` (the CPU build; the backend carries its own CUDA 12.8 runtime libraries), the llama-cpp CUDA 12 backend image `quay.io/go-skynet/local-ai-backends:<version>-gpu-nvidia-cuda-12-llama-cpp` as an image volume at `/backends/llama-cpp` (the directory name is the backend name, measured), and the model image as an image volume at `/models/qwen3.5-4b`, with the model YAML from the `localai-models` ConfigMap mounted by subPath under `/models` (Reloader restarts the pod when it or the Secret changes). It replaced llama-server on 2026-10-12 so the server matches the LocalAI vendor AI Workspace labels it with. Both LocalAI images are pinned `tag@sha256:digest` and read by Renovate's helm-values manager (confirmed on the Dependency Dashboard 2026-10-12, where the backend's bare `image:` line under `persistence` and the model image both appear); a rule groups them with a three-day wait. It serves two models: the embedding model nomic-embed-text-v1.5 Q8_0 (`nomic-embed-text-v1.5`, from `images/nomic-embed-text-v1.5`, 768 dimensions, `embeddings: true` on the llama-cpp backend, added 2026-10-18 for AI KB's knowledge bases and any other client), and the chat model Qwen3.5-4B Q4_K_M (`qwen-3.5-4b`, from `images/qwen3.5-4b`), with `context_size` 65536 split into four 16384-token slots (`parallel:4`, `kv_unified:false`; the KV cache costs 32 KiB per token because only 8 of its 32 layers hold one, so 2 GiB next to the 2.55 GiB weights on the 8 GiB GTX 1080), `max_tokens` 4096 as the default answer length (200 at first, which cut every AI Workspace reply mid-sentence, because the app sends no `max_tokens` when the listing carries no context size), thinking off at the server (`reasoning_effort: none`; a request can turn it on), and `cache_ram` 1024. The key is a legacy LocalAI API key, which grants full admin to whoever holds it and closes every route but `/healthz`, `/readyz` and discovery to everyone else (measured), so the gallery endpoint and runtime settings are disabled as well; it reaches the clients through `ai-workspace-secret` (`LOCALAI_API_KEY`, used server-side for `LOCALAI_API_HOST` only), `grafana-secret` (`LOCALAI_API_KEY`, expanded into the LLM app's `secureJsonData.openAIKey`) `matherlynet-secret` (`playground_model_key`) and `ai-kb-secret` (`LOCALAI_API_KEY`, filled into the `ai-kb-models` ConfigMap); Langfuse has no copy, because its project LLM connection takes the key in the UI. The pod runs as uid 65534 on a read-only root with emptyDirs at `/backends`, `/models`, `/configuration`, `/data` and `/tmp` (the last two capped at 1Gi). The container requests 8Gi of memory and is limited to 16Gi, because the pod's idle RSS was 7.5Gi on v4.11.0 with the four 16384-token slots and it was OOM-killed three times on 2026-10-18 under AI KB ingestion bursts (measured: `kubectl top` 7492Mi, `lastState` OOMKilled); on v4.12.1 it measured 661Mi idle and 1.5Gi after inference (2026-10-25), and the request and limit were left as they are. The official image defaults every gallery on, so `LOCALAI_GALLERIES`, `LOCALAI_BACKEND_GALLERIES` and both autoload switches are off, `LOCALAI_DISABLE_HARDWARE_DEFAULTS` keeps the auto-tuner from overriding the ConfigMap, and `LOCALAI_LOAD_TO_MEMORY` preloads the model so `/readyz` means loaded. Its `/v1/models` lists only `id` and `object` and it has no `/props`; AI Workspace keeps function calling on without that hint, and its context window is set once per user in the model options. `tool_choice: required` is not honoured by llama.cpp with this model (measured 2026-10-12), so clients send `auto`. A NetworkPolicy admits only the `ai` namespace and namespaces labelled `localai.ai/client: "true"`, and denies all egress. The optional `oidc_client_id` and `oidc_client_secret` pair (an OIDC client created by hand in Pocket ID with the callback `/oauth2/callback`, needing `[pocket_id]`) turns the WebUI on at `localai.${SECRET_DOMAIN}` on the internal gateway behind a copy of Hubble's `SecurityPolicy` (Pocket ID sign-in, `cluster_admins` only), and the NetworkPolicy then admits the `network` namespace; LocalAI serves the UI shell to anyone, so the user pastes the API key once on its `/app/login` page (measured; `/login` is 404), which keeps it in a `token` cookie, and the gallery endpoint and runtime settings stay off. AI Workspace v2026.10.12.2 and later read the model's `context_size` and `parallel` option from `/api/models/config-json/<id>` with the key, a route that answers 404 while the WebUI is off, so keep the pair set. The Pascal kernels are PTX the driver compiles on every container start (no persistent cache; add a `local-path` volume at `CUDA_CACHE_PATH` if the measured start time ever matters). The `public` fixture sets the section.
