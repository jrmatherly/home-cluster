# AI Workspace (`[ai_workspace]`)

- `[ai_workspace]` in `cluster.toml` (the ID and secret of an OIDC client created by hand in Pocket ID for the app's own sign-in, with the callback `https://ai.<domain>/api/auth/callback/oidc` and the logout callback `https://ai.<domain>/signin`, plus an `auth_secret` of at least 32 characters, set all together, needing `[pocket_id]` and `[postgres.backup]`; optional `allowed_emails` (addresses and `@domain` rules) and `admin_emails` (addresses, each admitted by `allowed_emails` when that is set, or the validator refuses the config, as the app would at startup); an optional `browsing_token` (letters and digits, at least 32); an optional `public` flag, which needs `pocket_id.public`; and an optional `[ai_workspace.env]` table of extra server-side env vars, keys `^[A-Z][A-Z0-9_]*$`, with the keys the templates set or depend on refused, every `AUTH_*` the templates set included, while `AUTH_OIDC_NAME` stays settable) gates the `ai-workspace` namespace, which enforces the `restricted` pod security level. `ai-workspace/ai-workspace` is AI Workspace (`ghcr.io/jrmatherly/ai-workspace`, a copy of big-AGI built from `~/dev/ai-workspace`), a multi-model chat UI on the app-template chart at `ai.${SECRET_DOMAIN}` on the internal gateway. It signs users in itself with Pocket ID (Better Auth over OIDC), so its route has no gateway `SecurityPolicy`: a lapsed gateway session answers the app's streaming API calls with a 302 they cannot follow. Pocket ID's "allow users to edit their own account details" must stay off, because the app links a Pocket ID sign-in to the account with the same email. A NetworkPolicy admits only the `network` namespace, because the gateway is the only intended path and the sign-in rate limit keys on the forwarded client address. It runs `next start` on 3000 as uid 1001 with a read-only root and emptyDirs at `/tmp` and `/app/.next/cache`; chats stay in the browser's IndexedDB, so the pod has no volume. Its probes request `/api/trpc/backend.listCapabilities`, a cheap JSON procedure, because the app has no health route; that request also loads the auth configuration, so a bad `AUTH_*` value fails the probe by design. Its server state is the CloudNativePG cluster `ai-workspace-db` (two instances, WAL archiving and a daily backup at 05:00): users, sessions, linked accounts and shared chat links; both `POSTGRES_*` variables come from the generated `ai-workspace-db-app` Secret. A `Database` object adopts the `app` database and keeps the `vector` extension (pgvector, shipped in the `standard` image) present in it for the Knowledge Base, because pgvector is not trusted and the app role cannot create it. The schema is applied by `prisma migrate deploy` from the HelmRelease's `migrate` controller, a Job on the same image anchor annotated as a Helm pre-install and pre-upgrade hook, so new pods start on the schema they expect and a failed run fails the release while the old pods keep serving; its `wait-for-vector` init container polls `pg_extension` through `prisma db execute` until `vector` exists, because on a fresh install nothing orders the operator's `CREATE EXTENSION` before the hook and the app role cannot create it (measured on the image: exit 1 while missing, 0 once present); the HelmRelease `timeout` is 15m for that reason, and the Service names its `controller` because a second controller exists. `AUTH_SECRET`, `AUTH_OIDC_CLIENT_SECRET`, the two email lists (so the household's addresses stay out of the public repo) and the `[ai_workspace.env]` entries are in the always-rendered `ai-workspace-secret` Secret; never change `auth_secret` casually, because it signs everyone out. When `nvidia_enabled`, `LOCALAI_API_HOST` points at LocalAI, `LOCALAI_API_KEY` in the Secret carries its key, and the namespace carries the `localai.ai/client` label. Vendor keys are bring-your-own in the browser unless added to `[ai_workspace.env]`. The image is pinned to its CalVer release tag by digest, and Renovate follows the tags. The gitignored `private/ai-workspace-setup.md` lists the setup steps. `browsing_token` adds `browserless`, a plain Deployment and Service (browserless Chromium, pinned by digest) that the app drives for Browsing through `PUPPETEER_WSS_ENDPOINT` in `ai-workspace-secret`, which also carries the bare token as `BROWSERLESS_TOKEN` for the browserless pod, so one rotation restarts both through Reloader. Its root filesystem stays writable, because Chromium's crashpad handler fails to start read-only (measured), with a 2Gi ephemeral-storage limit. The fence covers the in-cluster pod only: the app lets a member set their own websocket endpoint in Browsing settings, and the app pod has no egress policy, so that path is unfenced until the ai-workspace release that removes the member-set endpoint and checks target addresses (planned, 2026-10-11). Any member can make it fetch any URL, so its NetworkPolicy is an SSRF fence: ingress from the app only, egress to DNS in `kube-system` and to TCP 80 and 443 outside the computed `private_cidrs` (RFC 1918, CGNAT, link-local, six reserved ranges and the pod, service and node CIDRs), the list the ai-kb egress policy shares. The `public` fixture sets the section with `public = true`, an allowlist, an admin admitted by a domain rule, one env key and `browsing_token`.
