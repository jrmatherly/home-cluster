# It's a Plan (`[itsaplan]`)

- `[itsaplan]` in `cluster.toml` (a `better_auth_secret`, an `app_encryption_key` and a RustFS key pair, set all together, needing `[postgres.backup]` and `[rustfs]`) gates the `itsaplan` namespace, which enforces the `restricted` pod security level. `itsaplan/itsaplan` is It's a Plan, an issue tracker and project board with AI agents as members, from its chart (`oci://ghcr.io/croffasia/charts/itsaplan`, pinned by `OCIRepository` tag; the chart version is the release and its `appVersion` the image tag) at `plan.${SECRET_DOMAIN}` on the internal gateway, with no gateway `SecurityPolicy`, because the app has its own login (email and password, passkeys). The first account registered becomes the instance admin (the "god" role), so Jason registers first; a Pocket ID sign-in is configured afterwards in the app's god mode (Integrations, Auth provider, callback `<API_URL>/api/auth/oauth2/callback/oidc`) and is stored in the database, not in the HelmRelease. It is a PoC as of 2026-11-06.
- The api lives under `/api` on the web's host, which the chart's own Ingress cannot do but the HTTPRoute can: the `/api` prefix is rewritten to `/` (`URLRewrite`, `ReplacePrefixMatch`) on the way to `itsaplan-api:3000`, the `/.well-known/oauth-authorization-server`, `oauth-protected-resource` and `openid-configuration` prefixes reach the api unrewritten for MCP clients' OAuth discovery, and everything else goes to `itsaplan-web:3001`. With one hostname the session cookie is `__Host-better-auth.session_token` with no Domain, so no other app on the domain receives it; a second hostname would set it on `.${SECRET_DOMAIN}`. The public auth path is therefore `/api/api/auth/...` (measured in Docker through Caddy, 2026-11-06).
- The chart's three images (api, web, worker; the Telegram bot is off) set no `USER`, and run as uid 1001 on a read-only root with every capability dropped (measured in Docker, 2026-11-06). The web needs a writable `/app/apps/web/.next/cache` for its image cache, which a `postRenderers` patch adds as an emptyDir because the chart has no volume value for the web; without it every optimized image logs an unhandledRejection. The api's `migrate` init container applies the migrations on every start and, before an upgrade with pending migrations, dumps the database to `/backups` first; the chart mounts an emptyDir there, so the dump would succeed and die with the pod, and `SKIP_PRE_MIGRATION_BACKUP` is exactly `"1"` because the CloudNativePG cluster is the backup (a fresh install never dumps, so a missing or read-only `/backups` only shows on the first upgrade, measured in Docker). The probe's database was Postgres 17 and a code search found no `CREATE EXTENSION` in the migrations (2026-11-06); the first rollout on the catalog's Postgres 18 under the `app` role proves it.
- Its stores: the CloudNativePG cluster `itsaplan-db` (two instances, WAL archiving and a daily backup at 06:00 UTC; the chart's `externalDatabase.url` is filled through `valuesFrom` from the `uri` key of the generated `itsaplan-db-app` Secret, so no database password is in sops) and the RustFS bucket `itsaplan-attachments` (the `rustfs_consumers` entry `itsaplan`; the namespace carries `rustfs.storage/client`, and its Kustomization depends on `rustfs-provision`). The other four secrets reach the chart's own Secret through `valuesFrom` from `itsaplan-secret` as a whole `values.yaml` document, because Flux splits a `targetPath` value on commas. Telemetry is off on the api and the worker. A NetworkPolicy admits the `network` namespace on 3000 and 3001, because the app reads the client address from `X-Forwarded-For`, and the app's own pods on 3000 (the web's server side and the worker call the api). Egress is not fenced; the app refuses outbound requests to private addresses on its own, with `SSRF_ALLOWED_HOSTS` for exceptions. Never change `app_encryption_key`: the stored provider keys become unreadable. Git webhooks from GitHub cannot reach an internal-only instance, and the bucket has no volume backup yet.
- The gitignored `private/itsaplan-setup.md` lists the setup steps. The `public` fixture sets the section, and the invalid fixtures `partial-itsaplan` and `itsaplan-without-rustfs` cover its checks.
