# restart-reset

- `kube-system/restart-reset` is an hourly CronJob (`concurrencyPolicy: Forbid`, so runs never overlap) that evicts pods whose last restart is over an hour old, so restart counts left by a switch or gateway reboot or an API outage reset on their own. It was daily at 10:00 UTC until 2026-10-12, when that left a 09:21 EDT burst in place for a day. Each run evicts at most one pod per owner, and only when every pod of that owner is Ready, then waits for the replacement, so a two-replica Deployment or a CloudNativePG cluster with several stale pods clears over several hours, not two. Only a Deployment's pod or a CloudNativePG instance qualifies: StatefulSet, DaemonSet, Job and static pods are skipped, so is a one-replica Deployment no PodDisruptionBudget selects (a PDB selecting through `matchExpressions` does not count), and so is a CloudNativePG primary (label `cnpg.io/instanceRole=primary`), because evicting it would be a failover. Those skipped pods keep their counts until something else replaces them. A pod that restarted within the hour is left alone, so a real crash loop is never churned; a restart with no `finishedAt` counts as now, so that pod is left alone too. A failed wait logs `wait failed <ns>/<owner>` and fails the Job. The wait for an evicted pod is 240 s, past the 180 s smart shutdown a replica with a client waits out. The one-per-owner path had not run on a real eviction as of 2026-11-01, when the 19:00 and 20:00 UTC runs found no eligible pod and logged nothing. It runs kubectl and jq from the `alpine/k8s` image as uid 65534 with a ClusterRole limited to reading pods, Deployments, ReplicaSets, CloudNativePG clusters and PDBs and creating evictions. `.github/template-tests/e2e/restart-reset-select.test.sh` runs the rendered filter over fixtures (`just configure` first).
