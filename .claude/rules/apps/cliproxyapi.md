# CLIProxyAPI and CPA-Manager-Plus (`[cliproxyapi]`)

- `[cliproxyapi]` in `cluster.toml` (a `management_key`, an `api_key` and a `manager_admin_key`, set all together, needing no other section) gates the `llms` namespace, which enforces the `restricted` pod security level. `llms/cliproxyapi` is CLIProxyAPI (`eceasy/cli-proxy-api`), an OpenAI-, Anthropic- and Gemini-compatible proxy that pools subscription logins (Claude, Codex and others) behind one client key, at `llms.${SECRET_DOMAIN}` on port 8317. `llms/cpa-manager` is its management UI, CPA-Manager-Plus (`ghcr.io/seakee/cpa-manager-plus`), at `llms-admin.${SECRET_DOMAIN}` on port 18317. Both are on app-template, on the internal gateway only, with no gateway `SecurityPolicy`: the manager's `CPA_MANAGER_ADMIN_KEY` is its only login, and clients send `api_key` as a bearer token. It is a PoC as of 2026-11-06.
- Git seeds the proxy's config once. `cliproxyapi-secret` holds a whole `config.yaml`, mounted read-only at `/seed`, and the `seed-config` init container copies it to `/data/config.yaml` only when that file is absent. The app rewrites the file at start (it replaces the plaintext `management.secret-key` with a bcrypt hash) and persists every management-API write to it, so a read-only file makes those writes answer 500 (measured in Docker, 2026-11-06). After the first start the manager UI owns the config, and a change to the seed in Git reaches a running instance only if the volume's copy is deleted (`kubectl exec -n llms deploy/cliproxyapi -c app -- rm /data/config.yaml`, then `kubectl rollout restart deploy/cliproxyapi -n llms`, because init containers run once per pod and the seed Secret is mounted only in `seed-config`). That re-seed discards every setting made in the UI (client keys, routing, provider API keys) and keeps `auths/`. Rotating `management_key` or `api_key` in `cluster.toml` therefore needs that re-seed: the manager's Secret updates on its own through Reloader, the proxy's hash does not, and the two stop agreeing. Whether the manager takes a changed `CPA_MANAGEMENT_KEY` env once it has stored one encrypted with `data.key` is unverified. The manager keeps the plaintext management key in its own Secret and stores it encrypted with `/data/data.key`; losing that file makes the stored key unrecoverable.
- Measured in Docker on the pinned images (2026-11-06). Both images set no `USER`, and both run as uid 1000 on a read-only root with every capability dropped. The proxy writes only under `/data` (`config.yaml`, `auths/` with the OAuth token files and `kv.db`) and answers `/healthz` with no key (`/health` is 404). The image bakes `TZ=Asia/Shanghai` and a `TZ` env did not change the log stamps (measured live), so they read +08:00. `server.port` must stay in the seed: without it the app binds `:0` and the probe on 8317 kills the pod (measured live, 2026-11-06). The manager writes only to `/data` (`data.key`, `usage.sqlite` and its WAL, a lock file, `usage-imports/`), gets a `/tmp` emptyDir (it stayed empty, but was not proven unneeded), and answers `/health` with no key. Exactly one manager subscribes to a proxy's usage queue, so it runs one replica. The collector picks its transport once at start: with the proxy down it fell back to HTTP polling, two `GET /v0/management/usage-queue` a second in the proxy's log, and a restart with the proxy up chose `subscribe` (measured live, 2026-11-06), so a `wait-for-proxy` init container holds the manager until the proxy's `/healthz` answers. `kubectl exec -n llms deploy/cpa-manager -- sh -c 'wget -qO- --header "Authorization: Bearer $CPA_MANAGER_ADMIN_KEY" http://127.0.0.1:18317/status'` shows the transport. The first rollout left the proxy HelmRelease stalled (`MissingRollbackTarget`: every release had failed its five-minute wait, the install on the `args` bug and two upgrades while the pod was fixed by hand), and `flux reconcile helmrelease cliproxyapi -n llms --reset` cleared it once the Deployment was healthy. Both Deployments use `Recreate`, and both volumes are 1Gi `local-path` claims with `forceRename` and `retain: true`, because each holds the only copy.
- `trusted-proxies` is the pod CIDR, because the gateway forwards the client address and the app bans an address after five bad management keys. `disable-control-panel: true` turns off the bundled panel, which the app would otherwise download from GitHub; `/management.html` is 404 on the proxy. `usage-statistics-enabled: true` feeds the manager's usage pages, and `redis-usage-queue-retention-seconds: 3600` (the maximum; the default is 60) keeps an hour of usage in the proxy's memory so a manager restart loses nothing. `routing.cooldown.save-cooldown-status: true` writes `.cds` files next to the auth files so a throttled login stays out of rotation across a restart. `requests.nonstream-keepalive-interval: 30` sends blank lines on long non-streaming answers; the gateway's `requestTimeout` is already `0s`, so this guards only Envoy's stream idle timeout (inferred, not measured). The proxy refreshes OAuth tokens every 15 minutes (`core auth auto-refresh started (interval=15m0s)` in its start log, 2026-11-07). Settings tuned on 2026-11-07 and left at defaults on purpose: round-robin routing with session affinity (one hour; a Claude Code session stays on one login for its prompt cache), `model-level-cooling` off (a Max plan's limits are per account, not per model), cloak mode `auto`, no header defaults or device-profile pinning (upstream gives no recommendation), request logging, plugins, pprof and commercial mode off. The Antigravity, quota-fallback (`switch-project`, legacy Gemini) and multimedia settings do not apply to Claude logins.
- Editing `/data/config.yaml` through `kubectl exec` (with `sed -i` or a `cat >` rewrite) does not trigger the file watcher: the management API still answered the old values until `kubectl rollout restart deploy/cliproxyapi -n llms` (measured 2026-11-07, twice). Change settings in the manager's Config Panel, which persists and reloads, or restart after an exec edit. `GET /v0/management/config` with the management key returns the live in-memory config and is the check.
- The manager runs with `USAGE_ACCOUNT_ACTIONS_ENABLED=true`: a record-only review queue of revoked or invalid logins (the "Auth Issue To-Do List"). `USAGE_ACCOUNT_ACTIONS_AUTO_DISABLE` and `USAGE_QUOTA_COOLDOWN_ENABLED` stay off: auto-disable is not reversed by any worker and needs a re-login, and the quota cooldown worker only reads Codex and xAI signals. The Health Inspection (server inspection) feature covers Codex and xAI only, so its schedule stays disabled with Claude logins. Settings set by env are locked in the manager UI.
- Provider logins are added in the manager. It returns an authorization URL whose redirect is `http://localhost:54545/callback` (Claude) or `http://localhost:1455/auth/callback` (Codex). The browser lands on a failing localhost page, and the whole URL from the address bar is pasted into the manager's callback field. Measured 2026-11-07: three Claude accounts added this way, each as `auths/claude-<id>-<account>.json`, picked up without a restart; `/v1/models` listed 19 Claude models and a `claude-haiku-5-5` request answered through `/v1/messages` and `/v1/chat/completions`; the manager's Credential Management page showed all three Available on their plan after Refresh quota. A second account needs a private window. The manager's Source File Editor shows the client key in plaintext to anyone signed in. To test the client API without the key leaving the cluster, `kubectl exec` into the manager pod and let `wget` read the key from `/v0/management/api-keys` with `$CPA_MANAGEMENT_KEY` into a shell variable (the inner pipes need the sandbox off).
- NetworkPolicies admit the `network` namespace on each app's port, and the proxy also admits the manager's pods on 8317. Egress is open: the proxy dials the providers, plus an antigravity version check and the Grok CLI version from npm at start and every 3 hours.
- Every proxy setting tuned by hand goes into the seed in Git as well, because a redeploy re-seeds from it and the UI's copy on the volume is not backed up; manager settings go in its HelmRelease env, which locks them in the UI. Usage Maintenance: automatic archive retention stays off (`USAGE_ARCHIVE_RETENTION_ENABLED`, default false, 30 days), because one user's events fit the 1Gi volume for a long time (4.6 MB after the first day, 2026-11-07) and the first archive deletion freezes the manager's priced-model structure. Offline compaction (`compact-usage`) needs the manager stopped: `kubectl scale deploy/cpa-manager -n llms --replicas=0`, then a pod on the `cpa-manager` claim running `cpa-manager-plus compact-usage --db-path /data/usage.sqlite` (the image's entrypoint with that subcommand, uid 1000; needs free space at least the database size), then scale back to 1. Not rehearsed.
- Not done: no volume backup (the OAuth tokens and the manager's `data.key` exist only on the volumes), no metrics, no provider API keys in `cluster.toml`. The gitignored `private/cliproxyapi-setup.md` lists the setup steps, and `docs/src/content/docs/apps/cliproxyapi.mdx` is its scrubbed copy. The `public` fixture sets the section, and the invalid fixture `partial-cliproxyapi` covers its all-or-none check.
