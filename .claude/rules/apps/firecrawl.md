# Firecrawl (`[firecrawl]`)

- `[firecrawl]` in `cluster.toml` (`enabled`, needing `[cliproxyapi]` and `[redis]`; `model`, default `claude-sonnet-5-5`, is the `MODEL_NAME` of every model call; the vault item `firecrawl` holds `POSTGRES_PASSWORD`, at least 24 letters and digits) gates the `firecrawl` namespace, which enforces the `restricted` pod security level. `firecrawl/firecrawl` is a self-hosted Firecrawl (`firecrawl/firecrawl`), a web scraping API with scrape, crawl, map, search and extract, at `firecrawl.${SECRET_DOMAIN}` on the internal gateway and at `firecrawl-api.firecrawl.svc.cluster.local:3002` in the cluster. It exists so It's a Plan's agents and later apps do not need the paid cloud API. The plan is `docs/superpowers/plans/2026-11-23-firecrawl.md` (gitignored). Built 2026-11-23, not rolled out: the plan's Task 5 holds the live checks, and nothing below marked "Docker" has run on Kubernetes.
- No login. `USE_DB_AUTHENTICATION=false` means the API takes no key, and real authentication needs a Supabase database (`SELF_HOST.md`, read). Jason chose on 2026-11-23 to serve it on the LAN anyway, so any LAN device can call it and spend the CLIProxyAPI logins through extract. The boundary is the internal gateway plus the `firecrawl-api` NetworkPolicy, which admits the `network` namespace and, when `itsaplan_enabled`, the `itsaplan` namespace on 3002. A gateway API-key check on the route is the follow-up if that becomes a concern; whether Envoy Gateway's check accepts the `Authorization: Bearer` header the Firecrawl CLI sends is not verified.
- One app-template release, four controllers, each a Deployment with `Recreate`, a read-only root and every capability dropped: `api` (`ghcr.io/firecrawl/firecrawl`, uid 1000, `node dist/src/harness.js --start-docker`, which runs the API and every worker in one container as upstream's Compose file does), `playwright` (`ghcr.io/firecrawl/playwright-service`, uid 1000), `rabbitmq` (`docker.io/library/rabbitmq:3-management`, uid 999) and `postgres` (`ghcr.io/firecrawl/nuq-postgres`, uid 999). The chart names the Services `firecrawl-<controller>` and labels pods `app.kubernetes.io/controller` (measured with `helm template` on 5.3.0). Redis is the namespace's own instance from `components/redis` at `redis:6379`, with the password from `redis-auth` in both `REDIS_URL` and `REDIS_RATE_LIMIT_URL`; the chart sorts env names, so `REDIS_PASSWORD` precedes the two URLs that expand it (checked in the render). `enableServiceLinks` is false, because the Services would inject `FIRECRAWL_*_PORT` variables. The upstream Helm chart is not used: it splits the workers into Deployments that request over 25 G and defaults to third-party images.
- The Playwright command is `node dist/api.js`, not the image's `pnpm start`: corepack downloads pnpm into a home directory that does not exist and exits on the read-only root (Docker, 2026-11-23).
- The queue Postgres is Firecrawl's own image: Postgres 17 with `pg_cron` preloaded on the `postgres` database, and `nuq.sql` creating `pgcrypto`, `pg_cron` and the `nuq` schema at initdb only. So `POSTGRES_DB` stays `postgres`, and the database is not a CloudNativePG cluster. It, RabbitMQ and every `/tmp` are `emptyDir`: a pod restart loses in-flight crawls and stored results, which expire after 24 hours anyway, and a new Postgres pod runs `nuq.sql` again. `PGDATA` is a subdirectory, because initdb refuses a mount root it does not own. Reloader restarts `api` and `postgres` together when the password changes, and the fresh `emptyDir` takes the new one. The only claim in the namespace is Redis's 1Gi. Nothing here is backed up.
- Model calls go to `OPENAI_BASE_URL=http://cliproxyapi.llms.svc.cluster.local:8317/v1` with CLIProxyAPI's client key (the `cliproxyapi` item's `API_KEY`, read into `firecrawl-secret` as `OPENAI_API_KEY`). Firecrawl calls the Responses API, `POST /v1/responses`, for extract and for a `/v2/scrape` with a `json` format (Docker, with a stub in place of the model), and CLIProxyAPI answered that path for `claude-haiku-5-5` with a completed response (Jason, on the cluster, 2026-11-23). The full path from Firecrawl to the proxy has not run. Page content leaves the cluster, and extract draws on the same Claude logins as Claude Code. With the model endpoint answering 500, scrape, map, crawl and search still passed (Docker). `/v2/extract` reports itself deprecated in favour of the `json` format.
- Search tries Fire-engine (not published), then SearXNG when `SEARXNG_ENDPOINT` is set, then DuckDuckGo (`apps/api/src/search/v2/index.ts` at `v2.11.816`, read). The endpoint is rendered only when `ai_kb_searxng`, as `http://searxng.ai-kb.svc.cluster.local:8080`, and that SearXNG's policy then admits the API pod. Search answered with no endpoint set (Docker). From one home address some SearXNG engines are suspended at times, so the fallback may answer instead.
- What a self-hosted stack cannot do: screenshots and page actions need Fire-engine (a screenshot request fails with `Engines tried: []`, Docker), and Agent, Browser, interact and the product, menu, audio and video formats are cloud-only or need undocumented services. `/v2/team/credit-usage` answers 500 with a JSON body, which is why It's a Plan's credential check needs the fork change below.
- Egress. The API fetches pages itself as well as through Playwright, so `firecrawl-api` allows DNS, the namespace's pods, CLIProxyAPI on 8317, SearXNG on 8080 when deployed, and public addresses with `private_cidrs` excluded; `firecrawl-playwright` allows DNS and those public addresses; `firecrawl-backends` gives RabbitMQ and Postgres no egress. Firecrawl has a guard of its own: a scrape of a private container address returned success with empty Markdown and the target saw no request (Docker). Whether it holds for a hostname that resolves to a private address is not measured.
- Measured in Docker on 2026-11-23, on API `2.11.816`: ready in about 12 seconds; after the tests the API held 2.2 GiB, Playwright 190 MiB, Postgres 134 MiB, RabbitMQ 128 MiB and Redis 11 MiB. The requests and limits come from those numbers and upstream's Compose limits (8 G and 4 G). Whether RabbitMQ accepts its default `guest` account from another pod is not measured; an `ACCESS_REFUSED` line in the API log means it does not, and the fix is `RABBITMQ_DEFAULT_USER` and `RABBITMQ_DEFAULT_PASS` from a vault field, carried in `NUQ_RABBITMQ_URL`.
- Updates. The API image is tagged several times a day, and the Playwright and Postgres images publish `latest` only. `.renovaterc.json5` pins the two by digest, keeps all three out of the Tier 1 digest automerge and groups them into one Monday PR that is never automerged. A new Postgres digest takes effect on the next pod, whose `emptyDir` is new. Read the release's `docker-compose.yaml` diff before merging.
- It's a Plan cannot use this instance until its fork accepts a base URL: `packages/agent-tools/src/tools/firecrawl/client.ts` at `3aea4b7b` hardcodes `https://api.firecrawl.dev/v2`. The brief went to the It's a Plan session on 2026-11-23. After that release, set `SSRF_ALLOWED_HOSTS` to the API's Service host in It's a Plan's HelmRelease and add a credential with the base URL `http://firecrawl-api.firecrawl.svc.cluster.local:3002/v2` (the plan's Task 6).
- The gitignored `private/firecrawl-setup.md` lists the setup steps, and `docs/src/content/docs/apps/firecrawl.mdx` is its scrubbed copy. The `public` fixture sets the section with SearXNG, `career-ops-proxy` sets it without and with another `model`, and the invalid fixtures `firecrawl-without-cliproxyapi` and `firecrawl-without-redis` cover its checks.
