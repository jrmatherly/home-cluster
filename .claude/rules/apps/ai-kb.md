# AI KB (`[ai_kb]`)

- `[ai_kb]` in `cluster.toml` (a `jwt_secret` of at least 32 characters, an `aes_key` of exactly 32 letters and digits and an `admin_email`, set together, needing `[postgres.backup]`, `[redis]` and an ingress mode other than `none`) gates the `ai-kb` namespace, which enforces the `restricted` pod security level. `ai-kb/ai-kb` is AI KB, a knowledge base with retrieval-augmented chat, from its own chart (`oci://ghcr.io/jrmatherly/ai-kb/charts/ai-kb`, built from `~/dev/ai-kb`) at `ai-kb.${SECRET_DOMAIN}` on both gateways, with no gateway `SecurityPolicy`, because the app has its own login. The external route answers 404 for `/api/v1/auth/register` through an Envoy Gateway `HTTPRouteFilter`, so accounts are created from the LAN; once the OIDC pair is set, `DISABLE_REGISTRATION=true` (rendered only then, because before that the form is the only way to create an account) turns password sign-up off as the app's `invite_only` mode, which also refuses registration by invitation, a first Pocket ID sign-in creates an account, and a registration mode saved in the app's system settings takes precedence. `admin_email` reaches the app as `AIKB_BOOTSTRAP_SYSTEM_ADMIN_EMAIL`, which promotes that account at startup while no system administrator exists, so the first restart after that account exists makes it the admin. `AIKB_IM_PLATFORMS` allows Slack, Telegram and Mattermost only, `AIKB_AUDIT_RETENTION_DAYS` is 365, and `STORAGE_ALLOW_LIST` is `local,s3,minio`. `app.docsUrl` sets `AIKB_DOCS_URL` to `https://ai-kb.${SECRET_DOMAIN}/docs/`, the base of every docs link in the UI, because the chart derives it only with its own ingress on; `AIKB_GITHUB_LINK_ENABLED` is `true`, which shows the links to the GitHub repository that the app hides by default. The optional `oidc_client_id` and `oidc_client_secret` pair (an OIDC client created by hand in Pocket ID with the callback `/api/v1/auth/oidc/callback`, needing `[pocket_id]`) adds a Pocket ID sign-in next to the password form through `OIDC_AUTH_*` env vars (the chart has no OIDC values), with the secret read from `ai-kb-secret`, and `OIDC_AUTH_EXTENSION_RETURN_URLS` (always rendered) lists the browser extension's store-assigned origins, Chrome Web Store then Edge Add-ons, from the ai-kb repo's `extension/store/listing.md`, so a new store listing changes it; `SSRF_WHITELIST_EXTRA` then names `auth.${SECRET_DOMAIN}`, because pods resolve it to the internal gateway's private address, which the app's SSRF-safe HTTP client refuses for discovery otherwise. A Pocket ID sign-in links to the account with the same email, so Pocket ID's "allow users to edit their own account details" must stay off. When `nvidia_enabled`, the `ai-kb-models` ConfigMap is the app's `builtin_models.yaml` (mounted through the chart's `app.extraVolumes`, `BUILTIN_MODELS_CONFIG` names it), declaring LocalAI's chat and embedding models as built-in defaults visible to every workspace (provider `generic`, base URL with `/v1`, 768 dimensions, the key as `${LOCALAI_API_KEY}` from `ai-kb-secret`), the namespace carries the `localai.ai/client` label, and `SSRF_WHITELIST_EXTRA` names the LocalAI Service, because the app's provider code uses its SSRF-safe client too. The chart renders four Deployments (`app`, the Go API on 8080; `frontend` and `website`, nginx on Service port 80; `docreader`, gRPC on 50051) and a `data-files` volume on `local-path`, so `app` uses `Recreate`; its bundled Postgres, Redis and Ingress are off, so the values set `externalDatabase.host` and `externalRedis.addr`, which the chart requires then. The HTTPRoute mirrors the chart's Ingress: `/api` to `app`, `/docs` to `website`, everything else to `frontend`. Its data is in the CloudNativePG cluster `ai-kb-db` (one instance, because the community pg_search refuses to start on a standby, measured 2026-10-17; 10Gi, WAL archiving and a daily backup at 05:30), which loads `pg_search` from ParadeDB's extension image as an image volume (`paradedb-extension:<version>-18-trixie`, whose major and Debian release must match the catalog image, which already ships pgvector), and its initdb SQL creates `uuid-ossp`, `vector`, `pg_trgm` and `pg_search` and hands them to the `app` role, because the app role cannot create the untrusted ones and its migrations run `ALTER EXTENSION pg_search UPDATE`, which only the owner may (measured 2026-10-17: a `Database` object's extensions stay owned by `postgres`, and the first install also raced the app's migrations against that object). Its task queue and streams are the namespace's Redis from `components/redis`. The chart's own Secret is filled through `valuesFrom`: the database password from the generated `ai-kb-db-app` Secret, the Redis password from `redis-auth`, and `jwtSecret` and `systemAesKey` from the sops Secret `ai-kb-secret` as a whole `values.yaml` document, because Flux splits a `targetPath` value on commas. The first `valuesFrom` entry is the plain ConfigMap `ai-kb-flate-defaults` (`flate-defaults.yaml`), placeholders for the values the chart marks required and flate cannot read offline; every later entry overwrites it, so the cluster never runs on them (`.claude/rules/flux-apps.md`, 2026-11-08). A NetworkPolicy admits the `network` namespace on 8080, the chart's own pods on 8080 and the app pod alone on 50051 (and 7687 with Neo4j), because the app trusts the forwarded client address. A second one, `ai-kb-egress`, selects the app pod only (`app.kubernetes.io/component: app`) and allows DNS, its Postgres, Redis and docreader, then per flag Neo4j (`graph` pods, 7687), LocalAI (`ai`, 8080), `network` on Envoy's pod port 10443 plus the internal gateway's address on 443 for Pocket ID (in case the policy sees the packet before Cilium's translation), RustFS (9000) and Langfuse (3000), and TCP 80 and 443 to public addresses only, with the private, link-local, CGNAT, pod, service and node ranges and six reserved ranges (`127.0.0.0/8`, `0.0.0.0/8`, `192.0.0.0/24`, `198.18.0.0/15`, `224.0.0.0/4`, `240.0.0.0/4`) excluded through the computed `private_cidrs`, which browserless's fence loops over too. A third, `ai-kb-docreader-egress`, gives the docreader only DNS and those public addresses, because it fetches member URLs behind the app's SSRF guard alone; the app does OCR and storage, so a future docreader feature that dials the cluster needs a rule. The pg_search extension image pin is a CNPG `image.reference`, which a `customManagers` regex rule in `.renovaterc.json5` reads for Renovate; Docker versioning keeps it on `-18-trixie` tags. The optional `neo4j_password` (letters and digits, at least 32; `ai_kb_neo4j`) turns on the chart's Neo4j for GraphRAG (`neo4j.enabled`, the password in the `ai-kb-secret` values document; a Deployment with `Recreate` on a 10Gi `local-path` claim, pod label `app.kubernetes.io/component: graph`), and the ingress NetworkPolicy then admits the app pod on 7687; Neo4j stores the password on its first start, so a later change must also be made inside Neo4j, and the app tries Neo4j 30 times two seconds apart and then exits, so a fresh enable restarts it until Neo4j answers. The optional `searxng_secret` (letters and digits, at least 32; `ai_kb_searxng`) adds `ai-kb/searxng`, SearXNG for the app's web search, on the app-template chart, internal and JSON only (no route, `formats: [json]`, image proxy and rate limiter off, so no Valkey): a short `settings.yml` in the `searxng-settings` ConfigMap mounted by `subPath` at `/etc/searxng/settings.yml`, because the entrypoint checks that the image's directory exists and writes a settings file only when none is there; no `secret_key` in it, because `SEARXNG_SECRET` from `searxng-secret` overrides it and the app refuses to start on the default; uid 977 on a read-only root with every capability dropped, emptyDirs at `/tmp` (its SQLite caches) and `/var/cache/searxng`, `enableServiceLinks: false` (the Service name would inject `SEARXNG_PORT`), `/healthz` probes, and a 192Mi request (about 135 MiB idle and 150 MiB after eight concurrent searches, measured in Docker 2026-10-18); a NetworkPolicy admits only the app pod on 8080 with egress to DNS and public 80 and 443, and the Service host is in `SSRF_WHITELIST_EXTRA` with an egress-fence rule to it. Its tags are `<year>.<month>.<day>-<commit>`, several a day, so a `.renovaterc.json5` rule reads them with regex versioning. From one home address some default engines answer with a CAPTCHA at times and show under `unresponsive_engines`. The provider is added in AI KB's Settings > Web Search with the Instance URL `http://searxng.ai-kb.svc.cluster.local:8080`. Changing `jwt_secret` signs everyone out; never change `aes_key`, because the API keys and credentials it encrypted become unreadable. The four images are pinned `tag@sha256:digest`, and Renovate follows them, grouped with the chart as "AI KB". The chart is pinned by `OCIRepository` tag (`0.5.10`). The optional `rustfs_access_key` and `rustfs_secret_key` pair (set together, needing `[rustfs]`) makes AI KB a RustFS consumer (`ai_kb_rustfs`): the `rustfs_consumers` entry `ai-kb` with bucket `ai-kb-files`, the namespace label `rustfs.storage/client`, the chart's `env.STORAGE_TYPE: s3` with the `S3_*` settings in `extraEnv` (path style, no TLS, the pair from `ai-kb-secret`), and the RustFS Service in `SSRF_WHITELIST_EXTRA`, because the app's S3 client validates its endpoint with the SSRF guard too (and the EXTRA list is the one an admin's edit of the allowlist in the app's settings cannot replace); its Kustomization then depends on `rustfs-provision`, because the app checks its bucket at startup. A new workspace stores its files in the bucket; a workspace that exists keeps the backend recorded at its creation until it is switched in the workspace settings, and files already uploaded are not moved (measured in the app's source). The bucket has a nightly tar in R2 once `[volume_backup]` is set, after the 05:30 database backup (`.claude/rules/apps/volume-backup.md`). The optional `tracing = true` (needing `[langfuse]`, off by default: AI KB wraps its chat, embedding, rerank, VLM and ASR models and its knowledge ingest and post-process paths in Langfuse tracers, so traces carry full prompts and answers and the chunk text of every ingested document; Langfuse creates the project keys on its first start only, so a later change to the pair in `cluster.toml` must also be made in Langfuse's project settings, or every export gets 401 silently) sets `LANGFUSE_HOST` to the `langfuse-web` Service, `LANGFUSE_ENVIRONMENT` `home` and the project key pair from `[langfuse]` through `ai-kb-secret` (the app turns tracing on when both keys are set), and labels the namespace `langfuse.tracing/client`, which Langfuse's NetworkPolicy admits on 3000; the exporter is the stock OTLP client, not the SSRF-safe one, so its host is not in `SSRF_WHITELIST_EXTRA` (read in the app's source at the pinned tag). The `public` fixture sets the section with `tracing = true`, and the invalid fixtures `ai-kb-bad-aes-key`, `ai-kb-without-backup`, `ai-kb-without-redis`, `partial-ai-kb`, `ai-kb-rustfs-without-rustfs`, `partial-ai-kb-rustfs`, `ai-kb-tracing-without-langfuse`, `ai-kb-neo4j-without-section`, `ai-kb-searxng-without-section` and `ai-kb-oidc-without-pocket-id` cover its checks.
