# Adding or changing a Flux app

Flux reconciles `kubernetes/` from Git. During the template stage, edit the `.j2` sources under `template/config/kubernetes/`. After `just template tidy`, edit `kubernetes/` directly. The layout is the same in both.

- `apps/<namespace>/kustomization.yaml` sets `namespace:`, includes the `../../components/sops` component, and lists `./namespace.yaml` plus each app's `./<app>/ks.yaml`. A new app is not deployed until it is listed there.
- `apps/<namespace>/<app>/ks.yaml` is a Flux `Kustomization`. Every existing app uses these settings, so copy them from `apps/default/echo/ks.yaml.j2`:
    - `path: ./kubernetes/apps/<namespace>/<app>/app`
    - `interval: 1h`
    - `prune: true`
    - `targetNamespace: <namespace>`
    - `sourceRef` set to the `flux-system` GitRepository
    - `postBuild.substituteFrom` set to the `cluster-secrets` Secret, which provides `${SECRET_DOMAIN}` and the other cluster values
- `wait: false` is the default. Nine apps set `wait: true` (`arc-controller`, `flux-operator`, `cloudflare-dns`, `cloudnative-pg`, `plugin-barman-cloud`, `csi-driver-nfs`, `media-shared`, `rustfs`, `rustfs-provision`), and `cert-manager` uses `healthChecks`. Use `dependsOn` only for a real ordering need: `flux-instance` depends on `flux-operator`, and an app with a Postgres database depends on `cloudnative-pg` and `plugin-barman-cloud` (both in `cnpg-system`), because its manifests use their CRDs. A RustFS consumer (`ai-kb`, `langfuse`, `itsaplan`) depends on `rustfs-provision` in `rustfs`, because its key pair has to exist before it starts, and `ai-kb` with tracing also depends on `langfuse`. `home-cluster-runners` depends on `arc-controller`, `rustfs-provision` on `rustfs`, each media app on `media-shared`, and `media-shared` on `csi-driver-nfs`.
- `apps/<namespace>/<app>/app/` holds a `kustomization.yaml` that lists `helmrelease.yaml`, `ocirepository.yaml`, and any extra manifests. The `HelmRelease` uses `chartRef: {kind: OCIRepository, name: <app>}`, and the `OCIRepository` pins the chart with `ref.tag`. When upstream publishes no OCI chart, a `helmrepository.yaml` holds a `HelmRepository` instead and the `HelmRelease` pins the chart with `spec.chart.spec.version`.
- Renovate updates chart tags and images in these files without annotations, because the `home-operations/renovate-presets` default extends the flux, kubernetes, and helm-values managers to `.yaml.j2`. Don't add `# renovate:` comments here.
- Metrics. kube-prometheus-stack's Prometheus selects every ServiceMonitor and PodMonitor in the cluster. An app on app-template declares its scrape in the HelmRelease's `serviceMonitor` values, which render the ServiceMonitor with the chart's own selector labels; a standalone monitor file is for targets the chart does not render, such as `components/postgres/podmonitor.yaml.j2`. An app with a NetworkPolicy admits the `observability` namespace on the metrics port only, as `pegaprox` does. A Grafana dashboard ships as a `configMapGenerator` entry in the app's `kustomization.yaml`, with the JSON under `app/dashboards/` as a verbatim upstream copy, `disableNameSuffixHash: true` and the label `grafana_dashboard: "1"`; the chart's Grafana sidecar watches that label in every namespace. A scrape credential goes in its own sops Secret and is referenced from the endpoint's `authorization.credentials`.
- Network policies. A NetworkPolicy naming the callers' namespaces is the default, and kubelet probes pass it (measured on `pocket-id`, 2026-10-31). A backend read through the API server's pod proxy (`kubectl cnpg status`, `kubectl get --raw .../services/<service>:<port>/proxy/...`) needs a CiliumNetworkPolicy with `fromEntities: ["kube-apiserver"]` on that port, because the call arrives as `reserved:kube-apiserver,reserved:remote-node`, which a NetworkPolicy cannot name, and one on `kener-db` broke `cnpg status` on 2026-10-31. `components/postgres/networkpolicy.yaml.j2` and `observability/kube-prometheus-stack/app/networkpolicy.yaml.j2` are the examples. An egress fence that admits public addresses loops over `private_cidrs` in its `ipBlock.except`. A policy that dials a gateway names Envoy's pod port 10443 in `network`, because Cilium's socket load balancer translates at connect time, plus the gateway's address on 443.
- Pod security. Each `namespace.yaml` sets `pod-security.kubernetes.io/enforce`: `restricted` by default, `baseline` on `network`, `privileged` on `observability` and `storage`. `flux-system` is the exception: the operator marks that namespace `kustomize.toolkit.fluxcd.io/ssa: Ignore`, so a label in its `namespace.yaml` never applied (measured 2026-10-31), and a Namespace patch in `flux-instance`'s HelmRelease sets `restricted` instead. `kube-system`, `kube-public`, `kube-node-lease` and `cilium-secrets` carry no level (read live 2026-10-31).
- HelmRelease defaults. A patch in `flux/cluster/ks.yaml.j2` gives every HelmRelease `RemediateOnFailure` with two retries and `remediateLastFailure: true`, so a failed upgrade rolls back. A release a rollback would break carries the label `home-cluster.io/remediation: manual`, which the patch's `labelSelector` leaves out, and writes its own `install` and `upgrade` blocks, as `pocket-id` does.
- A Secret goes in `secret.sops.yaml`. sops encrypts only `data` and `stringData`, per the `.sops.yaml` creation rules, so keep the keys readable. Put one Secret in each sops file: sops signs the whole file with one MAC, and Flux decrypts each Secret on its own, so a second document in the file makes both fail with `MAC mismatch`. A second Secret gets its own file, as `alertmanager-secret.sops.yaml` does. Never commit a decrypted secret.
- Validation runs kubeconform in strict mode against the home-operations schemas (`template/resources/kubeconform.sh`, which skips DNSEndpoint, Gateway, HTTPRoute, and Secret, because their hostnames hold Flux placeholders). CI also runs `flate test all --supply .github/flate/supply.yaml -p ./kubernetes/flux/cluster`, on pull requests only and in changed-only mode, so a push to main is never checked and a PR that adds a namespace tests the whole tree. From flate 0.7.0 every SOPS-encrypted value is unreadable, and `ai-kb`, `itsaplan` and `matherlynet` read a database value through `valuesFrom` from the `<app>-db-app` Secret that CloudNativePG generates in the cluster, which is never in Git, so the supply file holds placeholders for those Secrets and for each encrypted Secret a `valuesFrom` names; without it flate reports the three blocked, and with it all 162 pass (measured with 0.7.3, 2026-11-11). A new `valuesFrom` on an encrypted Secret needs an entry there. `cluster-secrets` is not supplied, because each namespace has its own copy, so `${SECRET_DOMAIN}` stays unresolved in CI (flate's `UnresolvedSubstitution` warning). Their charts also refuse to render without the values flate cannot read, so `itsaplan` carries an inline placeholder for `externalDatabase.url` (a `valuesFrom` entry with `targetPath` overwrites inline values, Flux docs) and `ai-kb` lists the plain ConfigMap `ai-kb-flate-defaults` first in `valuesFrom` (its `jwtSecret` arrives as a whole sops values document without `targetPath`, which inline values would override, while every later `valuesFrom` entry overwrites an earlier one), so the cluster never runs on a placeholder. With `--supply` in place, those two placeholders could go, which is untested. During the template stage, the Stop hook runs kubeconform on the `public` fixture.
- A binary with a file capability (`getcap` shows `cap_net_raw+ep` on Debian's `ping` and `traceroute.db`) cannot even start under the `restricted` level, because the container drops every capability and the kernel refuses to exec a file whose effective capabilities it cannot grant. Copy it in an init container (`cp` drops the capability) into an emptyDir and mount the copy over the original with `subPath`, as `kener` and `network-optimizer` do. The copy then opens an unprivileged ICMP socket, which `net.ipv4.ping_group_range` allows. No Talos patch sets it (checked 2026-10-19), so pods get the runtime's default; `network-optimizer` pins it to `0 2147483647` in `defaultPodOptions.securityContext.sysctls`, which `restricted` permits. A .NET app's `Ping` class shells out to `/bin/ping4` when it has no raw socket, so the copy fixes that path as well. Both were measured on the real images in Docker.
- Claim names. app-template names a lone claim after the release and adds the persistence key to every claim once there are two, so adding or dropping a claim renames the others, and with `local-path`'s `Delete` that destroys the data (2026-10-05, 2026-10-24). An app whose volume holds the only copy of its state sets `forceRename: <current claim name>` and `retain: true` on it, as `pegaprox`, `network-optimizer`, `actual-budget` and `influxdb` do; together they render as one `helm.sh/resource-policy: keep` annotation and no rename (measured on chart 5.3.0, 2026-11-02).
- Once the cluster is running, Flux applies these files. Don't `kubectl apply` them by hand, because `kubectl apply` and `kubectl delete` prompt for confirmation. Use `just kube reconcile` to make Flux pull now.
