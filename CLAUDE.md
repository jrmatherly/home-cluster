## Overview

A home Kubernetes cluster on Talos Linux, managed with Flux. The repo is a fork of `onedr0p/cluster-template`. You fill in one config file, `cluster.toml`, and makejinja renders it into the Talos, Kubernetes, Flux and bootstrap config.

- The repo is still at the template stage, so the template tooling is present. `just configure` has rendered `bootstrap/`, `kubernetes/`, `talos/` and `.sops.yaml`, and the cluster is bootstrapped and live. Flux reconciles `kubernetes/` from Git, so a config change reaches the cluster by re-rendering with `just configure`, then committing and pushing.
- `just template tidy` ends the template stage. It moves all template tooling to `.private/<timestamp>/`, and you cannot undo it.

## Build & Development Commands

`mise install` installs every pinned tool (`.mise/config.toml`, `.mise/conf.d/template.toml`). mise also sets `KUBECONFIG`, `TALOSCONFIG`, `SOPS_CONFIG` and `SOPS_AGE_KEY_FILE` to paths inside the repo. Run commands from the repo root.

Template stage:

- `just init` creates `cluster.toml` from `cluster.sample.toml`, plus `age.key`, `deploy.key` and `flux-webhook-token.txt`, skipping any that exist.
- `just configure` renders with makejinja, sops-encrypts every `*.sops.*` file, runs kubeconform on `kubernetes/`, and checks that topf can render `talos/`.
- `just template doctor` checks that the required files exist, that `cluster.toml` passes the schema, and that its sections follow the sample's order.
- `just template check-layout` checks that `cluster.toml` keeps its sections in the order of `cluster.sample.toml`. `just configure` runs it first.
- `just template schema` regenerates `cluster.schema.json` from the pydantic model.
- `just template test-helmfile` renders the bootstrap Helm charts. It needs network access.
- `just template reset` deletes the rendered output.
- `uv run --locked pytest template/scripts/test_validate.py -q` runs the validator tests.
- `uv run --locked --no-dev template/scripts/validate.py <file.toml>` validates one config and prints it as JSON.
- `taplo check --schema "file://$PWD/cluster.schema.json" ./cluster.toml` checks the TOML against the schema.

These commands come from the rendered `mod.just` files, and now work:

- `just bootstrap talos` and `just bootstrap apps` run the two bootstrap phases.
- `just talos render|diff|apply|apply-node <node>|upgrade-node <node>|upgrade-k8s|reset-node <node>` manage the nodes. `just talos status|drain|uncordon|resume <node>` take one out of service and back by host name: `drain` checks the other nodes and etcd, switches over its CloudNativePG primaries, then drains. `stop-node <node>` drains and powers it off for host maintenance, `reboot-node <node>` drains, reboots and resumes it, and `health` checks Talos, nodes, pods, Flux and CloudNativePG.
- `just kube primaries` lists the CloudNativePG primaries and their nodes, and `just kube switchover <cluster> <namespace> [replica]` promotes a replica with `kubectl cnpg promote` and waits for a healthy cluster.
- `just kube reconcile` forces a Flux reconcile.

Docs site (`docs/`, Nimbus on Astro): `docker build --build-context gitdir=.git --secret id=scrub_denylist,src=private/scrub-denylist.txt docs` lints, scrubs and builds the pages. `docs/scrub-check.sh` checks pages for private content, and lefthook runs it on staged pages under `docs/src/content`.

## Architecture

```text
cluster.sample.toml        documented config; copy to cluster.toml (gitignored)
cluster.schema.json        generated from validate.py; editors use it via the #:schema line
makejinja.toml             inputs template/overrides + template/config, output ./
justfile                   root; loads template/mod.just and the rendered mod.just files
template/
  config/                  *.j2 sources, mirrored into the repo root on render
    bootstrap/             helmfile/ (crds, apps), sops secrets, mod.just
    kubernetes/            apps/<namespace>/<app>/, components/sops, flux/cluster, mod.just
    talos/                 all/ (numbered patches), control-plane/, topf.yaml.j2, mod.just
  overrides/               extra makejinja input; *.partial.yaml.j2 are not rendered
  scripts/validate.py      pydantic model of cluster.toml: defaults, cross-field checks
  scripts/check_layout.py  section order of cluster.toml against the sample
  scripts/plugin.py        makejinja Plugin: validated config as data; key and tunnel readers as functions
  scripts/test_validate.py pytest for the validator
  resources/kubeconform.sh validation run by `just configure`
  mod.just                 `just template ...` recipes
.github/template-tests/    valid/ and invalid/ cluster.toml fixtures, e2e/ helpers
.github/workflows/         template-e2e, template-e2e-cluster and template-release CI, plus label sync, flate, model-images and docs-image
images/<model>/Dockerfile  model image recipes, built by the model-images workflow
docs/                      Nimbus (Astro) documentation site, Dockerfile and nginx.conf; built by docs-image.yaml
```

The data flows in one direction. `cluster.toml` goes through `validate.load()`, then `Plugin.data()`, then the makejinja render. The output lands in `bootstrap/`, `kubernetes/` and `talos/`, and Flux reconciles `kubernetes/` from Git.

## Code Conventions

- Edit the `.j2` source under `template/config/`, never the rendered copy. makejinja uses `#{ var }#` and `#% block %#`, and plain `{{ }}` passes through to the output.
- Area rules in `.claude/rules/` load when you open matching files. `templates.md` covers makejinja, `talos.md` covers topf and Talos patches, `flux-apps.md` covers the Flux app layout, and `validator.md` covers schema changes.
- Renovate updates chart and image versions in `.yaml.j2` files on its own. `# renovate:` comments are only for the pins its managers cannot find: the Talos and Kubernetes versions in `talos/topf.yaml.j2`, and the `prometheus-operator-crds` chart in `bootstrap/helmfile/crds.yaml.j2`.
- Formatting follows `.editorconfig`: 2 spaces, LF line endings, 4 spaces for Markdown and shell. oxfmt formats YAML, JSON, Markdown and TOML at width 100 across the whole tree, minus `.oxfmtrc.json`'s `ignorePatterns`, so TOML has no aligned `=` columns; the pre-commit hook formats staged files, and the stop hook and CI run `oxfmt --check .`.
- Python: `validate.py` subclasses `Model` (`extra="forbid"`), uses `Annotated` validators, and reports errors through `ConfigError` and `format_errors`, one per line. `plugin.py` uses single quotes, and `validate.py` uses double quotes.
- just recipes use `[doc()]`, `[group()]` and `[private]` attributes, and run under bash with `-euo pipefail`. They log through `just log <level> "<msg>" key value`, which calls `gum log`.

## Detected Patterns

- A `cluster.toml` schema change touches four places: `validate.py`, `cluster.sample.toml`, `cluster.schema.json` (from `just template schema`), and the test fixtures. `.claude/rules/validator.md` has the steps, and each invalid fixture carries a `# expect: <error message>` line that `test_invalid_fixture_rejected` matches. `cluster.sample.toml` is the layout of record: `cluster.toml` and the fixtures keep its section order and banner comments, a new section is scaffolded into `cluster.toml` by copying the sample's block into the same position, and `just template check-layout` fails a config whose sections are out of that order.
- Rendered YAML has to be oxfmt-clean: the Stop hook runs `oxfmt --check .` on the whole tree and on every fixture's render, and the lefthook pre-commit hook formats staged files (the upstream CI step that checks it skips on this fork).
- The whole `ai` namespace (`ai/localai` and its namespace and kustomization files) is wrapped in `#% if nvidia_enabled %#`, so it renders empty when NVIDIA is off.

It replaced llama-server on 2026-10-12 so the server matches the LocalAI vendor AI Workspace labels it with. Both LocalAI images are pinned `tag@sha256:digest` and read by Renovate's helm-values manager (confirmed on the Dependency Dashboard 2026-10-12, where the backend's bare `image:` line under `persistence` and the model image both appear); a rule groups them with a three-day wait. It serves two models: the embedding model nomic-embed-text-v1.5 Q8_0 (`nomic-embed-text-v1.5`, from `images/nomic-embed-text-v1.5`, 768 dimensions, `embeddings: true` on the llama-cpp backend, added 2026-10-18 for AI KB's knowledge bases and any other client), and the chat model Qwen3.5-4B Q4_K_M (`qwen-3.5-4b`, from `images/qwen3.5-4b`), with `context_size` 65536 split into four 16384-token slots (`parallel:4`, `kv_unified:false`; the KV cache costs 32 KiB per token because only 8 of its 32 layers hold one, so 2 GiB next to the 2.55 GiB weights on the 8 GiB GTX 1080), `max_tokens` 4096 as the default answer length (200 at first, which cut every AI Workspace reply mid-sentence, because the app sends no `max_tokens` when the listing carries no context size), thinking off at the server (`reasoning_effort: none`; a request can turn it on), and `cache_ram` 1024. The pod runs as uid 65534 on a read-only root with emptyDirs at `/backends`, `/models`, `/configuration`, `/data` and `/tmp` (the last two capped at 1Gi). The official image defaults every gallery on, so `LOCALAI_GALLERIES`, `LOCALAI_BACKEND_GALLERIES` and both autoload switches are off, `LOCALAI_DISABLE_HARDWARE_DEFAULTS` keeps the auto-tuner from overriding the ConfigMap, and `LOCALAI_LOAD_TO_MEMORY` preloads the model so `/readyz` means loaded. - `images/<model>/Dockerfile` is the recipe for a model image that LocalAI mounts as an image volume. It downloads the GGUF from Hugging Face at a pinned `REVISION`, checks `SHA256`, and copies it into a `scratch` image. The Model Images workflow (`.github/workflows/model-images.yaml`) builds and pushes it to `ghcr.io/jrmatherly/models/<model>` when `images/**` changes on `main`, and never rebuilds a tag that exists. - `kube-system/restart-reset` is an hourly CronJob (`concurrencyPolicy: Forbid`, so runs never overlap) that evicts every Running, fully Ready pod whose last restart is over an hour old, one at a time, so restart counts left by a switch or gateway reboot or an API outage reset on their own within two hours. It was daily at 10:00 UTC until 2026-10-12, when that left a 09:21 EDT burst in place for a day. Eviction honours PodDisruptionBudgets, static pods are skipped, and so is a CloudNativePG primary (label `cnpg.io/instanceRole=primary`), because evicting it would be a failover. A pod that is not Ready or restarted within the hour is left alone, so a real crash loop is never churned; a restart with no `finishedAt` counts as now, so that pod is left alone too. It runs kubectl and jq from the `alpine/k8s` image as uid 65534 with a ClusterRole limited to listing pods and creating evictions.
- `storage/local-path-provisioner` provides the default StorageClass `local-path`. Its volumes are directories under `/var/mnt/local-path`, declared as a Talos `UserVolumeConfig` in `talos/all/72-volumes.yaml`, so each volume is pinned to one node and has no size limit.
- `cnpg-system` holds the CloudNativePG operator (`cloudnative-pg`) and its backup plugin (`plugin-barman-cloud`). The plugin must run in the operator's namespace, and its TLS certificates come from cert-manager. The namespace enforces the `restricted` pod security level.
- `[postgres.backup]` in `cluster.toml` (endpoint, bucket and an access key pair, set all together or not at all) is the object store for Postgres backups. `components/postgres` renders only when it is set. An app with a database includes that component from its `app/kustomization.yaml`, which adds the `postgres-backup` ObjectStore and Secret and the `postgresql` ImageCatalog to the app's namespace, and its `ks.yaml` depends on `cloudnative-pg` and `plugin-barman-cloud` in `cnpg-system`. Backups land under the Cluster's name in the bucket, so Cluster names must be unique across namespaces. The component also adds a `postgres` PodMonitor that scrapes every instance in the namespace, and `cnpg-system/cloudnative-pg` holds the `postgres-backup` PrometheusRule (backup failed, backup older than 36 hours, WAL archiving failing). Its rules use the plugin's `barman_cloud_cloudnative_pg_io_*` metrics, because the `cnpg_collector_*` backup metrics stay at 0 with the plugin. The `public` fixture sets the section.
- `[observability]` in `cluster.toml` (a Grafana password, an InfluxDB password and an InfluxDB token, set all together or not at all) gates the whole `observability` namespace, which enforces the `privileged` pod security level for node-exporter. `kube-prometheus-stack` runs Prometheus, Alertmanager and Grafana, scrapes every ServiceMonitor, PodMonitor and rule in the cluster, and reaches etcd through the control-plane node addresses. The kube-state-metrics ServiceMonitor drops the `uid` label (`metricRelabelings` `labeldrop`), because FreeLens joins node metrics onto `kube_pod_info` by pod and namespace, and a pod recreated under the same name leaves two series differing only in `uid` until the old one goes stale, which fails the join. `influxdb` is InfluxDB 2 on the app-template chart, with org `home` and bucket `proxmox` created on the first start. Grafana and InfluxDB have routes on the internal gateway. Prometheus and Grafana have memory requests and limits set in the HelmRelease. The optional `proxmox_hosts` list (the Proxmox hosts' addresses, needing the other three) adds the `proxmox-hosts` ScrapeConfig, which scrapes node-exporter from Debian's `prometheus-node-exporter` package, installed by hand on each host, on port 9100, and the `proxmox-hosts` PrometheusRule, which alerts when `node_zfs_zpool_state` shows a pool not online (a REMOVED rpool mirror member froze cp-1's disk on 2026-10-12) or a host's exporter is down for 10 minutes, and a page needs `discord_webhook`; Cilium masquerades the scrape to the node's address, so a host firewall admits every node address on 9100, because any node may host Prometheus. The optional `grafana_oidc_client_id` and `grafana_oidc_client_secret` pair (an OIDC client created by hand in Pocket ID, needing `[pocket_id]`) adds a Pocket ID sign-in to Grafana next to the password form; only the Pocket ID group `cluster_admins` gets a role, as Grafana server admin, and everyone else is refused. The image ships its datasource plugins in a read-only directory, and Grafana's updater unloads a plugin before it fails to replace it there (this took the Prometheus and InfluxDB data sources down on 2026-10-06). So never list them in `[plugins] preinstall`; the HelmRelease sets the chart's `shadowBundledPlugins: true`, which hides that directory so Grafana's default preinstall list fetches them into the writable plugins directory on the volume, and `preinstall_auto_update: true` in `grafana.ini` keeps them current, because the chart turns it off otherwise. The experimental `pluginsAutoUpdate` feature toggle, with `plugins.update_strategy = minor`, also updates every non-core, unpinned, unprovisioned plugin between restarts, because the catalog publishes a bundled plugin's new version days after the Grafana release that carries it and the advisor flags the gap until then. ## Best Practices

- Never commit secrets or machine config. `.gitignore` covers `cluster.toml`, `age.key`, `deploy.key`, `flux-webhook-token.txt`, `cloudflare-tunnel.json`, `kubeconfig` and `talosconfig`.
- The Stop hook (`.claude/hooks/stop.py`) blocks the end of a turn while template changes fail. It runs when anything under `template/`, the sample, the schema, `makejinja.toml`, `pyproject.toml`, `uv.lock` or `.github/template-tests/` differs from `main` (on `main` itself, from HEAD, so a committed break is not re-checked). In a scratch copy it runs pytest and `oxfmt --check .`, renders every valid fixture and format-checks the output, and runs kubeconform and topf on the `public` fixture only; kubeconform is skipped offline, a second Stop with the same unchanged failure is let through, and the hook fails open on its own errors. For workflow changes, run `zizmor --offline .github/workflows/*.yaml` yourself.
- `.claude/settings.json` blocks reading the key files and asks before destructive commands: `reset`, `tidy`, `bootstrap`, `apply`, `upgrade`, `sops decrypt`, `kubectl delete`, and similar. Don't work around a prompt, for example with `yes |` or `--yes`.
- The `cluster-guard` mod (`.claude/skills/cluster-guard/`, see its README) is a hooks module that refuses Edit/Write/Bash writes into the rendered `bootstrap/`, `kubernetes/` and `talos/` trees (since 2026-10-10 a rendered path counts as a write only where the command writes it: a redirect target, a file given to `tee`, the destination of `cp`, either end of `mv`, or a file given to `sd`, `sed -i`, `perl -pi`, `yq -i`/`--inplace` or `sops -i`/`--in-place`, the root `.sops.yaml` included, in relative, `./`, `$PWD`, absolute or quoted form, so reading one into scratch is allowed; the mod's tests run from lefthook whenever its files are staged), refuses any Bash command segment that names `cluster.toml`, `age.key`, `deploy.key`, `cloudflare-tunnel.json`, `flux-webhook-token.txt`, `kubeconfig` or `talosconfig` outside `validate.py`, `check_layout.py`, `just template` recipes and `taplo check`, refuses node maintenance (the `just talos` drain, apply, upgrade, reset, stop and reboot recipes, plus raw `talosctl`, `topf` and `kubectl drain`) from 02:45 to 03:30 local, and counts re-encrypted `*.sops.*` files after configure, add, commit, restore, stash and checkout. The gitignored `.claude/skills/cluster-guard/.claude-plugin/types/` is where Claude Code lays type declarations for a mod it hot-reloads; `/reload-plugins` did not lay it, and a plugin folder added while a session is open loads only after that session restarts or runs `/reload-plugins` (both measured 2026-10-10). `.claude/settings.json` denies `Read(/cluster.toml)`, and the gitignored `.claude/settings.local.json` re-allows `./cluster.toml` for the sandbox so the parser path works.
- lefthook runs these on pre-commit: oxfmt, `just --fmt`, `mise fmt`, `mise lock`, zizmor, Ruff, shellcheck, markdownlint, and `claude plugin test` on `cluster-guard` when its files are staged. The `format-toml` job excludes `.mise/**`, because `.oxfmtrc.json` ignores that tree and oxfmt exits 2 when every file it is given is ignored (`mise fmt` formats those files). After you edit a mise config, commit the updated `.mise/mise.lock`.
- On macOS, use `sd` for regex replacements instead of `sed -i`.
