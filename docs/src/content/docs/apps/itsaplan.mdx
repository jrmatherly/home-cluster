This guide takes It's a Plan from the templates in Git to a working issue tracker, with Pocket ID as the way in. It's a Plan is an issue tracker and project board where AI agents can be members. The deployment itself is in Git: the `[itsaplan]` section of `cluster.toml` and `kubernetes/apps/itsaplan/`. It is a proof of concept, started 2026-11-06 on chart 1.10.0.

It is served at `https://plan.${SECRET_DOMAIN}` on the internal gateway, so the LAN reaches it and the internet does not, except for the one webhook path below when `git_webhooks` is on. The api lives under `/api` on the same host. The HTTPRoute strips that prefix on the way to the api, so the public sign-in path is `/api/api/auth/...`. Keeping one hostname also keeps the session cookie on `plan.${SECRET_DOMAIN}` alone.

## Fill the section

The section needs `[postgres.backup]` and `[rustfs]` to be set. Generate its four secrets, put them in the vault item `itsaplan` under the labels in the comments ([External Secrets and 1Password](/apps/external-secrets/)), and set `enabled = true` in the `[itsaplan]` section of `cluster.toml`:

```sh
openssl rand -base64 48 | tr -dc A-Za-z0-9 | head -c 48; echo   # BETTER_AUTH_SECRET
openssl rand -base64 48 | tr -dc A-Za-z0-9 | head -c 48; echo   # APP_ENCRYPTION_KEY
openssl rand -hex 16                                             # RUSTFS_ACCESS_KEY
openssl rand -hex 32                                             # RUSTFS_SECRET_KEY
```

<Aside type="caution">
Never change `APP_ENCRYPTION_KEY` once it is set. The app encrypts the provider keys it stores with it, and a new key makes them unreadable.
</Aside>

Then run `just configure`, commit and push.

The `rustfs-provision` Job reruns, because its list of consumers changed. It creates the `itsaplan-attachments` bucket and an account scoped to it.

## Watch the first rollout

```sh
kubectl get kustomization -n flux-system itsaplan
kubectl get cluster -n itsaplan itsaplan-db
kubectl logs -n itsaplan deploy/itsaplan-api -c migrate
kubectl get pods -n itsaplan
```

The Kustomization is Ready, and the CloudNativePG cluster `itsaplan-db` is healthy with two instances. The `migrate` log ends with the migrations applied and no `CREATE EXTENSION` failure, because the `app` role cannot create extensions. The api, web and worker pods are Running. The Telegram bot is off, so it has no pod.

## Register the admin

Open `https://plan.${SECRET_DOMAIN}` from the LAN and register. The first account becomes the instance admin, the `god` role. Sign-up stays open to the LAN after that, until you close it in god mode.

## Add the Pocket ID sign-in

God mode has no menu link in 1.10.0, so type `https://plan.${SECRET_DOMAIN}/god`. The provider page is `/god/auth-provider`, and the registration and login switches are under `/god/authentication`.

1. On `/god/auth-provider`, copy the redirect URI, `https://plan.${SECRET_DOMAIN}/api/api/auth/oauth2/callback/oidc`.
2. In the Pocket ID admin UI, add an OIDC client with that callback URL. Copy its client ID and secret.
3. Back on `/god/auth-provider`, paste the discovery URL `https://auth.${SECRET_DOMAIN}/.well-known/openid-configuration`, the client ID and the secret. Name the button and turn it on.
4. Turn on **Trust addresses from sign-in providers** only if Pocket ID is the only place accounts come from.
5. Sign in once with Pocket ID. Then, under `/god/authentication`, turn email and password sign-in off and set registration to `invite only` or `closed`. Pocket ID and passkeys are then the only ways in.

The provider settings live in the app's database, so nothing in Git changes. The app refuses outbound requests to private addresses, but it did not block discovery against `auth.${SECRET_DOMAIN}` (measured 2026-11-06).

## Browser push and Git webhooks

Both are off until a flag in `[itsaplan]` turns them on.

**Browser push** (`web_push = true`). Generate one VAPID key pair in a checkout of the app with `bun run web-push:keys`, and keep it: a new pair ends every browser subscription. Put three fields in the vault item `itsaplan`: `WEB_PUSH_VAPID_PUBLIC_KEY`, `WEB_PUSH_VAPID_PRIVATE_KEY` and `WEB_PUSH_SUBJECT`, a `mailto:` or `https:` contact for the push services. Then `just template secrets-check`, `just configure`, commit and push. Each member turns push on under Account, Preferences.

**Git webhooks** (`git_webhooks = true`, needs an ingress). A second HTTPRoute puts one path on the external gateway: `POST https://plan.${SECRET_DOMAIN}/webhooks/git/`. Every other path stays on the internal gateway, so the internet still cannot open the app. The route has no login in front of it, because a Git host sends no session; the app checks each delivery against the project's webhook secret. A BackendTrafficPolicy on the route allows 10 requests a second per Envoy pod and bodies up to 5 MiB, because the app sets no limit of its own there. After the push, connect the provider under Team settings, Git, then each project's Settings, Git. The payload URL shown there starts with `https://plan.${SECRET_DOMAIN}/webhooks/git/`.

## Known limits

- Without `git_webhooks`, GitHub webhooks cannot reach it, and pull request linking does not work.
- The Telegram bot is off.
- The `itsaplan-attachments` bucket has no nightly copy to R2 yet. A `[volume_backup]` entry could add one. The database is covered by CloudNativePG's WAL archive and its daily backup at 06:00 UTC.
- Egress has no NetworkPolicy. The app's own guard refuses private targets, with `SSRF_ALLOWED_HOSTS` for exceptions.
