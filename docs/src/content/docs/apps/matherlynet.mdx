This guide covers matherlynet, the public site at `https://${SECRET_DOMAIN}`, from the `[matherlynet]` section of `cluster.toml` to a release that answers through the Cloudflare tunnel. The site and its chart are built in the site's own repository, `<github account>/matherlynet`; this repo owns the namespace, the database, the routes, the securityContext and the NetworkPolicy. The deployment is in Git: `kubernetes/apps/matherlynet/` and the `[matherlynet]` bullet in `CLAUDE.md`.

Each step names its source. "Template" is `template/config/kubernetes/apps/matherlynet/`. "Sample" is the `[matherlynet]` block of `cluster.sample.toml`. "Site docs" is `docs/deployment.md` in the site's repository. "apps.md" is `.claude/skills/update-apps/references/apps.md`.

## Fill `cluster.toml`

1. `better_auth_secret` and `admin_email` turn the site on, set together (source, `template/scripts/validate.py`). The secret signs the site's sessions; changing it signs everyone out. `openssl rand -base64 32` makes one (sample).
2. The site needs `[postgres.backup]`, because its database holds accounts, and `ingress.mode = "cloudflare-tunnel"`, because the site trusts the client address Cloudflare reports (source, `validate.py`).
3. Set `admin_email` before that account's email is verified: the site promotes the admin account when its email becomes verified, never later. For a GitHub or Google account, set it before that account's first sign-in (site docs, section 2).
4. `smtp_url` is optional and must be a `smtps://` (implicit TLS, 465) or `smtp://` (STARTTLS, 587) URL. A bare host name is refused, because the site's mail library throws on it. Percent-encode a quote, backslash, space, dollar sign or at sign in the user or password (`%40` for `@`) (source, `validate.py`; sample). `mail_from` is the optional sender, and may carry a display name.
5. `github_client_id` and `github_client_secret` turn on GitHub sign-in, set both or neither; the same for the `google_*` pair (source, `validate.py`). The IDs go into the chart's `config.web`, the secrets into the sops Secret (template).
6. `playground = true` is optional and needs an NVIDIA node (source, `validate.py`). See "The playground" below.
7. Every optional field needs `better_auth_secret` and `admin_email`, because the site only runs when both are set (source, `validate.py`).
8. `just configure`, restore the unchanged sops files, commit and push.

## How the release is wired

The chart is `oci://ghcr.io/<github account>/matherlynet/charts/matherlynet`, pinned in `ocirepository.yaml.j2` (0.44.1 on 2026-10-19). CI in the site repository pushes a chart with each image from `main`. The version is `0.<run>.<attempt>`, `appVersion` is the commit, and the chart carries the web image digest, so a chart bump moves the image too (site docs, section 7; apps.md). There are no GitHub releases. The expected rendered diff of a bump is two lines, the `web_image` digest and `SENTRY_RELEASE`; anything more is a chart change to read (apps.md). Check what a version pins with:

```sh
helm show chart oci://ghcr.io/<github account>/matherlynet/charts/matherlynet --version 0.<run>.<attempt>
```

Values reach the chart in three layers (template, `helmrelease.yaml.j2`):

- `values.config.web.app_url` is `https://${SECRET_DOMAIN}`, plus the OAuth client IDs and the playground URL when set.
- `valuesFrom` the CloudNativePG Secret `matherlynet-db-app`, key `uri`, into `secrets.web.appdb_uri`.
- `valuesFrom` the sops Secret `matherlynet-secret`, a whole values document: `admin_email`, `mail_from`, `better_auth_secret`, `smtp_url`, the OAuth secrets and the playground key. It is a document because Flux splits a `targetPath` value on commas, and the two addresses are in it to keep them out of Git (template, `secret.sops.yaml.j2`).

The database is the CloudNativePG cluster `matherlynet-db`: two instances on 5Gi `local-path` volumes, Postgres 18 from the `postgresql` ImageCatalog, WAL archived to the backup bucket, and a daily backup at 03:00 UTC (template, `cluster.yaml.j2`, `scheduledbackup.yaml.j2`). The second instance keeps the site up when a node goes down.

## The `postRenderers` patch

The chart sets no securityContext, resources or annotations, and the namespace enforces `restricted`. A kustomize patch in `postRenderers` adds them to `matherlynet-web-deployment` (template):

- `runAsNonRoot`, `runAsUser: 1000`, `runAsGroup: 1000`, `seccompProfile: RuntimeDefault`. `runAsUser` is needed because the image's user is the name `node`, which the kubelet cannot check as non-root (site docs, section 7).
- For the `web` container: no privilege escalation, a read-only root, every capability dropped. The image needs no writable path (site docs).
- Requests of 100m CPU and 384Mi, a 768Mi memory limit.
- `reloader.stakater.com/auto: "true"`, because the pod reads its config through `envFrom`, and a Helm upgrade that changes only values does not restart it (site docs, section 8).

## Routes, the tunnel and DNS

Both routes are on `envoy-external` (template, `httproute.yaml.j2`):

- `${SECRET_DOMAIN}` goes to `matherlynet-web-service` on 4321.
- `www.${SECRET_DOMAIN}` answers a 301 to the apex. The redirect is required: better-auth trusts only `APP_URL`'s origin, so sign-in from `www` fails with `403 INVALID_ORIGIN`, and cookies are host-only (site docs, section 3).

The tunnel's ingress has an apex rule for `${SECRET_DOMAIN}` ahead of `*.${SECRET_DOMAIN}`, because the wildcard does not match the apex (source, `network/cloudflare-tunnel/app/helmrelease.yaml.j2`).

ExternalDNS creates the apex record but cannot own it: its ownership record would be named `k8s.cname-${SECRET_DOMAIN}`, which is outside the zone, so it is skipped. The apex record is never updated or deleted by ExternalDNS. If the route ever goes away, delete the apex record by hand in Cloudflare (template, the comment in `httproute.yaml.j2`).

## Who can reach the pod

The NetworkPolicy admits only the `network` namespace on 4321, because the site trusts the client address header Cloudflare sets (template, `networkpolicy.yaml.j2`). Its rate limiting keys on `cf-connecting-ip`, which any client could send to an exposed port (site docs, section 1).

The Cloudflare zone has rules outside Git, among them a rate limiting rule on `/api/playground` and skips that can exempt the home network, so a burst test from the LAN proves nothing. Test from a phone on cellular.

## The playground

With `playground = true` (template):

- The namespace carries `localai.ai/client: "true"`, which the [LocalAI](/apps/localai/) NetworkPolicy admits.
- `config.web.playground_model_url` is `http://localai.ai.svc.cluster.local:8080`, the base URL without `/v1`.
- `secrets.web.playground_model_key` is LocalAI's API key (`localai.api_key`), sent as a bearer token.

LocalAI serves the model as `qwen-3.5-4b`, the site's default model id since chart 0.42.1; the chart value `config.web.playground_model` overrides it (source, the chart's values).

The Cloudflare rate limiting rule on `/api/playground` must exist before the URL is set (site docs, section 8). With the URL unset, `/playground` is a browser simulation.

## Health check

From apps.md:

```sh
kubectl -n matherlynet rollout status deploy/matherlynet-web-deployment
curl -s https://${SECRET_DOMAIN}/ | grep -c pageswap
```

The rollout completes and the page has `pageswap`. The chart's own probes hit `/api/auth/ok`, which stays up while Postgres is down (site docs, section 7). After the first deploy behind a new tunnel, submit the sign-in form once: a `403 Cross-site POST form submissions are forbidden` means `X-Forwarded-Proto` is not arriving (site docs, section 3).
