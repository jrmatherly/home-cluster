This guide covers `ai/localai`: the API key, the three apps that call it, changing the model, the model settings, and how to check it. The deployment is in Git: the `[localai]` section of `cluster.toml` and `kubernetes/apps/ai/localai/`.

LocalAI runs on `k8s-gpu-1`, the worker on the GPU host that holds the GTX 1080 (8 GiB). Pods reach the API at `http://localai.ai.svc.cluster.local:8080`. The only route is the WebUI at `https://localai.${SECRET_DOMAIN}` on the internal gateway, which exists only when the WebUI's OIDC client is set in `[localai]` (see [The WebUI](#the-webui)).

Each claim names its source. "Source" is a file in this repo. "Measured" means it was run on the cluster on 2026-10-12, the day LocalAI replaced llama-server (commit `4d0ff9d`).

## What it is

- LocalAI from the official images, no custom build (source, `helmrelease.yaml.j2`). Three images: `localai/localai:v4.11.0` (the CPU build), the llama-cpp backend `quay.io/go-skynet/local-ai-backends:v4.11.0-gpu-nvidia-cuda-12-llama-cpp` as an image volume at `/backends/llama-cpp`, and the model `ghcr.io/<github account>/models/qwen3.5-4b:q4_k_m-e87f176` as an image volume at `/models/qwen3.5-4b`. The backend image carries its own CUDA 12.8 runtime; only the driver comes from the host.
- The backend directory must be named `llama-cpp`, because the directory name is the backend name. `cuda12-llama-cpp` fails with "backend not found" (measured in Docker).
- Two models (source, `configmap.yaml.j2`): the chat model Qwen3.5-4B Q4_K_M, named `qwen-3.5-4b`, and since 2026-10-18 the embedding model nomic-embed-text-v1.5 Q8_0, named `nomic-embed-text-v1.5`, 768 dimensions, `embeddings: true` on the same llama-cpp backend. nomic-embed expects the task prefixes `search_document: ` and `search_query: ` in the text.
- The whole `ai` namespace renders only when a node loads the nvidia kernel module (`nvidia_enabled`).
- The pod runs as uid 65534 on a read-only root. `/data` and `/tmp` are emptyDirs capped at 1Gi. The NetworkPolicy admits the `ai` namespace and namespaces labelled `localai.ai/client: "true"`, plus the `network` namespace when the WebUI is on, and denies all egress (source, `networkpolicy.yaml.j2`).
- Every gallery is off (`LOCALAI_GALLERIES`, `LOCALAI_BACKEND_GALLERIES` and both autoload switches), because the image defaults them on and would reach `index.localai.io` and Quay, which the NetworkPolicy drops. The gallery endpoint and runtime settings are always off. The WebUI is off unless its OIDC client is set (source, `helmrelease.yaml.j2`).

## Generate the key

`[localai] api_key` is required whenever a node loads the nvidia kernel module (source, `validate.py`, "localai.api_key is required when a node loads the nvidia kernel module"). It must be at least 32 letters and digits (source, `validate.py`, `ApiKey`).

1. Generate it:

    ```sh
    openssl rand -hex 32
    ```

2. Put it in `cluster.toml` as `api_key` under `[localai]`.
3. `just configure`, restore the `*.sops.*` files whose inputs did not change, commit and push.

The key is a legacy LocalAI API key. It grants full admin to whoever holds it, and it closes every route but `/healthz`, `/readyz` and discovery to everyone else (measured). That is why the gallery endpoint and runtime settings are disabled as well. Treat it like a root credential.

## The three consumers

Each client sends the key as a bearer token. One `just configure` writes it into four Secrets: `localai-secret` for LocalAI itself, and one per consumer (source, the templates named below).

| Consumer | Gate | How it gets the key | How it reaches LocalAI |
| --- | --- | --- | --- |
| AI Workspace | `[ai_workspace]` | `LOCALAI_API_KEY` in `ai-workspace-secret`, read through `envFrom` | `LOCALAI_API_HOST` in the HelmRelease. The key is used server-side for that host only. |
| Grafana's LLM app | `[observability]` | `LOCALAI_API_KEY` in `grafana-secret`, an env var on Grafana, expanded into the app's `secureJsonData.openAIKey` in the `grafana-llm-app` ConfigMap | `openAI.url` in that ConfigMap, with both abstract models mapped to `qwen-3.5-4b` |
| matherlynet's playground | `matherlynet.playground = true` | `playground_model_key` in the values document of `matherlynet-secret` | `playground_model_url` in the HelmRelease, the base URL without `/v1` |
| AI KB | `[ai_kb]` | Typed into the app's model provider form per tenant; nothing in Git carries it | The namespace carries the `localai.ai/client` label and the app's `SSRF_WHITELIST` names `localai.ai.svc.cluster.local`, because its SSRF guard refuses cluster addresses otherwise. Base URL `http://localai.ai.svc.cluster.local:8080/v1`, chat `qwen-3.5-4b`, embeddings `nomic-embed-text-v1.5`. |

Each consumer's namespace carries the `localai.ai/client: "true"` label under the same gate, which is what the NetworkPolicy admits. The three reached LocalAI with their keys on 2026-10-12 (measured).

## Change the model

The model is an image built from `images/qwen3.5-4b/Dockerfile`. It downloads the GGUF from Hugging Face at a pinned revision, checks its SHA-256, and copies it into a `scratch` image (source, the Dockerfile).

1. In the Dockerfile, update `REPO`, `REVISION`, `FILE`, `SHA256` and `TAG` together. `TAG` is `<quant>-<first 7 characters of REVISION>`, for example `q4_k_m-e87f176`. A new model gets its own `images/<model>/Dockerfile` in the same shape.
2. Commit and push to `main`. The Model Images workflow (`.github/workflows/model-images.yaml`) runs when `images/**` changes on `main`. It builds and pushes `ghcr.io/<github account>/models/<model>:<TAG>` and never rebuilds a tag that exists, because the cluster pins it by digest. The run summary prints `Pushed <image>@<digest>`.
3. A new GHCR package is private. Make it public in the package settings after its first push, because the kubelet pulls it with no pull secret (source, `CLAUDE.md`).
4. In `helmrelease.yaml.j2`, put `<image>:<TAG>@<digest>` in the `models-qwen` image volume. In `configmap.yaml.j2`, update `parameters.model` (`<directory>/<file>.gguf`), and the model name if it changes. A new name also means the ConfigMap key and the two `subPath` mounts in `helmrelease.yaml.j2` (`/models/<name>.yaml`), `LOCALAI_LOAD_TO_MEMORY`, and the Grafana mapping in `grafana-llm-app.yaml.j2`.
5. `just configure`, commit, push. The first start pulls the new image. A cold start took 4m01s (measured: backend pull 57 s, model pull 92 s, load 45 s); the HelmRelease timeout is 15m for that reason.

The two LocalAI images move with Renovate as one group; the model image is bumped by hand.

## The model settings

They are in the `localai-models` ConfigMap, mounted by subPath under `/models` (source, `configmap.yaml.j2`). A subPath mount never updates in place, so Reloader restarts the pod when the ConfigMap or the Secret changes (source, the `reloader.stakater.com/auto` annotation).

- Slots: `context_size: 65536` with the options `parallel:4` and `kv_unified:false`, so four slots of 16384 tokens each. The KV cache costs 32 KiB per token on this model, because only 8 of its 32 layers hold one, so 2 GiB next to the 2.55 GiB weights (source, the ConfigMap comment). `nvidia-smi` showed 5059 MiB of 8192 used (measured). A request longer than a slot gets HTTP 400.
- `max_tokens: 4096` is the answer length when a request sets none. AI Workspace sends none, because the model listing carries no context size. The first value, 200, cut every chat reply mid-sentence (measured 2026-10-12, commit `412d145`). 4096 leaves 12288 tokens of a slot for the prompt.
- Thinking: `reasoning_effort: none` turns Qwen3.5's thinking off at the server. A request can turn it on. With thinking on, most completion tokens go to `reasoning_content` (measured in Docker).
- `cache_ram: 1024`. `LOCALAI_DISABLE_HARDWARE_DEFAULTS` keeps LocalAI's auto-tuner from overriding these values (source, `helmrelease.yaml.j2`).

## Check it

```sh
kubectl -n ai exec deploy/localai -- curl -fsS localhost:8080/readyz
kubectl -n kube-system exec ds/nvidia-device-plugin -- nvidia-smi
kubectl -n ai exec deploy/localai -- curl -s -o /dev/null -w '%{http_code}\n' localhost:8080/v1/models
kubectl -n ai exec deploy/localai -- sh -c 'curl -s -o /dev/null -w "%{http_code}\n" -H "Authorization: Bearer $LOCALAI_API_KEY" localhost:8080/v1/models'
```

- `/readyz` answers 200 once the model is loaded. `LOCALAI_LOAD_TO_MEMORY` preloads the model at start, so ready means loaded, not merely listening. The startup probe allows ten minutes (source, `helmrelease.yaml.j2`). `curl` is in the image (measured).
- `nvidia-smi` runs from the device-plugin pod, because LocalAI's INFO log has no llama.cpp buffer lines to read the VRAM from (measured). Expect about 5 GiB of 8 used.
- `/v1/models` answers 401 without the key and 200 with it (measured).

A warm restart takes 45 s from pod start to Ready (measured).

## The WebUI

The WebUI is off by default. Setting `oidc_client_id` and `oidc_client_secret` under `[localai]` turns it on at `https://localai.${SECRET_DOMAIN}` on the internal gateway (source, `validate.py`, `localai_webui_enabled`). It renders the `localai` HTTPRoute on `envoy-internal` and the `localai` SecurityPolicy, puts the client secret in the `localai-oidc` Secret, and the NetworkPolicy then admits the `network` namespace, where the gateway runs (source, `kustomization.yaml.j2`, `networkpolicy.yaml.j2`).

The SecurityPolicy is a copy of Hubble's. The gateway signs users in with Pocket ID and admits only a token whose `groups` claim contains `cluster_admins` (source, `securitypolicy.yaml.j2`). LocalAI needs that sign-in in front of it, because it serves the WebUI shell, `/login` and the static assets to anyone (source, LocalAI v4.11.0, `core/http/auth/public_routes.go`).

1. Create a Pocket ID OIDC client as [the recipe on the Pocket ID page](/apps/pocket-id/#register-another-app-as-an-oidc-client) describes. Callback URL `https://localai.${SECRET_DOMAIN}/oauth2/callback`. Include the `groups` scope and restrict the client to `cluster_admins`.
2. Put the client ID and secret in `cluster.toml` as `oidc_client_id` and `oidc_client_secret` under `[localai]`.
3. `just configure`, restore the `*.sops.*` files whose inputs did not change (keep the new `localai-oidc` Secret), commit and push. Flux rolls the LocalAI pod, because `LOCALAI_DISABLE_WEBUI` changes.
4. Open `https://localai.${SECRET_DOMAIN}` and sign in with Pocket ID.
5. LocalAI's own sign-in page, `/app/login`, asks for a key (`/` redirects to `/app`, the SPA; the server path `/login` answers 404, measured). Paste the API key once. LocalAI checks it and keeps it in a `token` cookie (source, LocalAI v4.11.0, `core/http/routes/auth.go`, `POST /api/auth/token-login`).

The gallery endpoint and runtime settings stay off, so the WebUI cannot install models or change settings.

## Known limits

- No `/props`, and `/v1/models` lists only `id` and `object` (measured). A client that reads the context size or tool support from the server finds neither. AI Workspace keeps function calling on without that hint, and its context window is set once per user in the model options (source, `CLAUDE.md`).
- `tool_choice: required` is not honoured by llama.cpp with this model: on a prompt that needs no tool it writes junk up to `max_tokens`, while `auto` answers cleanly (measured 2026-10-12). Clients send `auto`.
- The first completion after a container start is slow. The GTX 1080 is Pascal, and its kernels are PTX that the driver compiles on every container start, with no persistent cache. The first completion took 15.2 s for 160 tokens, a warm one 3.4 s, about 47 tokens a second (measured). If the start time ever matters, add a `local-path` volume at `CUDA_CACHE_PATH`.
- LocalAI holds the whole GPU and only `k8s-gpu-1` has one, so it waits while that node is drained (see [Node maintenance](/operations/node-maintenance/)).
